# Merge and publication boundary

## Layout and ownership

两个项目分别位于`projects/amazon-keyword-library`与`projects/amazon-listing-pipeline`。根目录仅拥有仓库路由、项目登记和统一检查，不另写业务知识、判断边界、核心词或SKU筛选规则。原相对引用仍在各项目内解析；角色包只能按其当前登记版本装载。

迁移先在独立候选工作树进行，原项目与原始业务目录保持不动。关键词来源版本和逐文件哈希登记在`migration/keyword-source-lock.json`；可发布候选的适配及Listing来源记录也须在同目录形成独立清单。源文件保全与候选修改分别报告，不把脱敏或路径适配后的字节误称原样相同。

## Required publication checks

- 完整纳入获准的修正合同、Skills、知识、流程、能力/证据索引、依赖和必要资产，不只复制目录结构。
- 候选仅来自逐项审查的发布清单。原始聊天、输入输出、截图/运行日志、登录状态、真实任务ID/本机路径、凭据和未审查资产不能被批量暂存。
- 单项明确授权例外：2026-09-03用户在知悉真实ASIN、Alexa样本内容、评分和结论将公开后，允许Listing的`projects/amazon-listing-pipeline/.agents/skills/prioritize-amazon-insight-tags/assets/golden-tag-priority-workbook.xlsx`原样发布，SHA-256固定为`7ee355536f9ca806b82b1d91d08d8bec0f56f9ba90df99068a05707d8a28cb9c`。仅该文件与角色包内同字节必要副本适用，不制作空白替代、不改样本/公式/版式，不提升案例或P1状态；其他原始数据及任何凭据/本机身份不在授权内。发布清单必须逐路径登记这些副本，哈希不同则重新审查。
- 脱敏不得改业务阈值、流程、人口、Sheet结构、质量门、外部来源、用户确认边界或案例/P1事实。必要资产若不能安全发布，先报告阻塞，不能直接删掉资源或编造替代真实案例。
- 保留不可变旧包及原业务产物在本机，不将它们整体导入公共Git历史。公开候选与本机证据清单分开，日志不能作为用户凭据或数据的绕行发布渠道。
- 项目登记限定发现根；重复Skill身份只在显式部署/参考关系中允许，不可自动任选。缺失资源、链接越界、哈希漂移及错误项目根应失败。
- 统一入口运行每个项目的原检查；各项目已有机械回归不能因迁移被替换为只有表头或目录存在的检查。迁移后业务Run须重新锁定当前revision与任务cwd，不复用旧绝对路径。
- 测试/夹具只证明结构与机械合同，不证明真实来源可用、完整业务运行、节省比例、任务已加载或P1。

## Local recovery and GitHub

原工作区不就地转换；失败时保留候选和报告用于诊断，不覆盖原文件。关键词原接口修订为独立本地提交，整合变更在短期分支；只有审核范围、候选清单、测试及共享权限闭合后才推送PR，并以远端main回读为完成依据。不强推、不重写已有共享历史、不将尚未加载的旧任务当作新版本就绪。

本仓库继续使用既有GitHub目标；不新建远端仓库。公开署名使用用户确认的身份，不把自动生成的设备邮箱误带入新公开提交。
