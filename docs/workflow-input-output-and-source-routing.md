# 全流程输入输出与来源路由索引

本文件把两个项目已经拥有的字段合同、站点路由、来源优先级和状态语义集中到一个入口，供主任务、新电脑初始化和运行前预检使用。它是导航与一致性检查表，不接管各业务模块；发生冲突时仍以对应项目的 `AGENTS.md`、Skill 和直接合同为准。

## 1. 站点是全流程必填锁

主输入必须明确 `marketplace`，不得缺省后静默按美国站执行。主任务在创建 Run 前将站点规范化为下表中的稳定值，并把整行路由作为一个不可拆分对象传给所有副任务。

| marketplace | 商城域名 | 配送邮编 | 购物助手 | 提问语言 | Amazon 联想 |
|---|---|---:|---|---|---|
| `Amazon-US` | `amazon.com` | `10001` | Alexa for Shopping | 英语 | `amazon.com`、Department=`All`、已登录 |
| `Amazon-DE` | `amazon.de` | `80539` | Rufus | 德语 | `amazon.de`、Department=`Alle`或页面实际等义项、已登录 |

站点对象至少写入 Run、跨项目交接、来源记录和工作簿说明：`marketplace/domain/postal_code/shopping_assistant/prompt_language`。页面域名、邮编、语言或工具与锁定值不一致时：

1. 不继续采集，也不自行切回美国站；
2. 保存当前可见状态和发生步骤；
3. 标记 `marketplace_mismatch/needs_user_intervention`，通知用户介入；
4. 修复后从受影响的来源动作重新验证，不能把错站结果混入本 Run。

## 2. 来源与接口优先级

优先级按阶段定义，不存在一个覆盖所有环节的通用“网站 > MCP > Sorftime”链。

| 阶段 | 正式优先级 | 明确禁止 |
|---|---|---|
| SIF 竞品反查 | 已登录 SIF 网页完整结果；仅用户明确无法在当前设备/会话登录时，才用同提供商 SIF MCP | 用卖家精灵、Sorftime 或普通网页搜索替代 SIF 字段 |
| 关键词挖掘 | **卖家精灵网页完整官方导出 > 卖家精灵 MCP**；MCP 仅在已登录但网页完整导出链路不可用时启用 | Sorftime 网页或 MCP 参与关键词挖掘 |
| Amazon 联想 | 锁定站点的 Amazon 搜索框可见联想；内置浏览器 > 普通 Chrome 备用 | 搜索结果页、网页搜索、API 或其他站点联想 |
| 趋势 | **卖家精灵 MCP > Sorftime MCP**；一个 Run 只选一个提供商，切换时备用源从头重跑全部趋势人口 | 卖家精灵网页、Sorftime 网页、SIF、词根/近义词补月或跨源拼月 |
| Rufus/Alexa 洞察 | 锁定站点内的购物助手 | 商品页、评论、普通搜索或模型常识补答 |

Sorftime 官网只用于账户开通、MCP 配置与用量检查，不是正式采集入口。核心词锁定后，Amazon 联想与卖家精灵扩词必须在同一调度波次派发；不得等待其中一条完成后才启动另一条。

### 固定任务会话登录门

用户提交完整输入且主任务锁定站点后，立即引导用户完成固定八会话矩阵：Listing商品审计、五维洞察、标签网页核验、痛点频率、痛点口语表达和关键词Amazon联想六个Amazon拥有任务由用户逐任务手动登录；关键词SIF与卖家精灵拥有任务按输入表中的非敏感账户别名/凭据引用使用浏览器已保存凭据或本机密码管理器。每份回执绑定当前Task/host/dispatch；主任务或其他浏览器已经登录不能代替。八份齐全后才允许发起查询、提问、导出或联想采集。密码、验证码、Cookie和令牌不得进入聊天、工作簿、证据公开包或Git。SIF仅在用户明确批准且同提供商MCP已鉴权时按原备用条件处理。

## 3. Rufus/Alexa 的站点操作合同

### Amazon-US

使用 Alexa for Shopping 和英语问题。需要独立上下文的 Skill 继续按其美国站合同新建或清空会话。

### Amazon-DE

使用 amazon.de 内的 Rufus 和已经冻结的德语等义问题。德国站当前没有可依赖的 `New Chat` 控件，且刷新网页后上下文仍可能保留，因此：

- `context_independence=not_available`，不得把刷新写成“已清空上下文”；
- 不为清空上下文反复刷新，也不因该限制阻断德国站测试；每个问题自身必须包含目标 ASIN；
- Rufus 按钮是面板开关。面板已经可见时直接输入，不能再次点击按钮把面板隐藏；只有面板未显示时才点击打开；
- 每次回答仍核验商品/ASIN身份。错配只影响对应槽位，保留技术和身份状态，不用其他来源补答。

## 4. Listing 主输入字段

`full_pipeline` 的单一输入工作簿按以下固定表头读取：

| Sheet | 固定字段 |
|---|---|
| 新品基础信息 | `ASIN｜产品类型｜产品人群画像｜使用场景｜用途｜核心卖点｜市场选择`；最后一列必选`Amazon-US`或`Amazon-DE`，内部规范化为`marketplace` |
| 新品基础配置 | `产品尺寸参数｜产品包装参数｜包含配件/组件｜卖点` |
| 竞品对标ASIN | `价格竞品｜颜色竞品｜尺寸竞品｜材质竞品｜风格竞品` |
| 市场竞品ASIN池 | `ASIN｜父体ASIN｜是否启用｜采样用途｜备注` |
| 登录准备 | `服务｜账户别名｜凭据引用｜登录方式｜说明`；固定SIF/卖家精灵/Amazon三行，禁止密码等秘密字段 |

进入关键词项目时，另外传递三组输入的路径/区块与 SHA-256、目标 Amazon 类目、多稳定产品类型细分是/否、站点、品牌、当前 SKU 事实、直接竞品、双方 Run/revision 和合同哈希。关键词项目不反向修改 Listing 的三张基础表。

## 5. Listing 输出目录与核心字段

| 编号 | 文件/对象 | 固定结构摘要 |
|---:|---|---|
| 01 | Amazon 五维洞察 | 主结果字段 `ASIN｜用途｜场景｜人群｜特点｜痛点`，另含说明/状态 |
| 02 | 商品信息审计与竞品横向 | 本品表 `抓取指标｜用户提供信息｜购物助手抓取内容｜状态｜差异提醒`；竞品横向为 ASIN 加九类字段 |
| 03 | 本品优势与卖点排序 | 两 Sheet：优势点六列、卖点排序六列，字段以审计 Skill 合同为准 |
| 04 | 痛点频率 | 痛点明细 11 列；频率统计 8 列，分母只含有效且完成的 ASIN |
| 05 | 标签优先级 | 固定五 Sheet：标签、Coverage、Listing Expression、市场分类/参数对比、内容优先级 |
| 06 | SKU 可用关键词库 | 固定五个来源/流量 Sheet，每表前五列为 `关键词分类｜关键词｜中文翻译｜月搜索量｜ABA月排名` |
| 07 | 核心卖点决策包 | 七类信息校准、证据与初步排布；进入人工确认门 1 |
| 08 | 痛点口语表达 | 仅对已选中且合格的痛点运行，可选 |
| 09 | 埋词与标签映射 | 四 Sheet，计划与正文后的实际覆盖分开记录 |
| 10 | Amazon Listing 交付 | schema 2.0 固定 14 Sheet；正文确认后才装配并进入最终 QA |

04 的痛点明细固定为：`ASIN、产品标题、处理状态、触发问题、标准化痛点、具体表现、证据来源、Supporting wording、购物助手原始回答、是否计入统计、排除原因`。频率统计固定为：`排名、标准化痛点、出现ASIN数、有效ASIN总数、痛点频率、涉及ASIN、典型Supporting wording、数据状态`。

## 6. 关键词项目输入输出

第一板块原始业务表：

- SIF 七列：`竞品ASIN、SIF返回序号、英文关键词、ABA排名、搜索量、Top3点击份额、Top3转化份额`；
- 卖家精灵四列：`英文关键词、中文翻译、ABA月排名、月搜索量`；
- Amazon 联想来源事件记录触发输入、原始建议、顺序、站点、部门、邮编、浏览器、状态与证据指针。

最终交付恰好两个顶层对象：`过程性文件/` 与 `<Run_ID>-最终关键词词库.xlsx`。最终工作簿恰好八个可见 Sheet，顺序固定为：

1. `最终关键词决策总表`
2. `SKU事实卡`
3. `品类产品通用词库`
4. `二类词`
5. `关键词竞争性分析`
6. `关键词趋势性分析`
7. `词频统计`
8. `否词库`

总表覆盖第一板块机械去重全人口并保持 51+N 列；`二类词`固定 16 列；竞争性分析固定 12 列。更细字段和动态列仍由关键词项目各直接合同拥有。

## 7. 告警、阻断与交付状态

图标只是显示，不是状态机：`⚠️/❗` 必须同时出现文字状态、影响范围与继续/停止结论，单独一个感叹号不能阻断整条流程。

- 行级/字段级告警：保留缺口，影响对应事实或行；下游在合同允许时继续，常见结果为 `completed_with_gaps`。
- 模块阻断：站点错配、身份错配导致来源不可采信、锁/人口/Schema不闭合、来源无权限或关键技术动作未执行；只阻断该模块及依赖后代。
- 最终门：用户跳过独立 QA 时，装配检查仍执行，但必须记录 `QA=cancelled_by_user/not_executed`、`delivery_status=incomplete`、`P1=false`，不能显示为通过。

## 8. 新电脑拉取后的必检

1. 拉取后先运行根结构检查，不把克隆成功当作角色已装载。
2. Listing 每个任务必须读取 `task-packages/registry.json` 当前版本；不得沿用聊天中记住的旧包路径。关键词任务按当前项目 AGENTS 和拥有 Skill 装载。
3. 先列出现有任务和侧栏可见性。侧栏缺失不等于任务不存在；核对项目归属、Task ID、host、cwd 后再决定是否创建，避免重复任务。
4. 输入与站点锁定后立即进入固定八会话登录门：六个Amazon拥有任务由用户逐任务手动登录；SIF和SellerSprite拥有任务按`登录准备`中的非敏感引用使用本机已保存凭据。全部Task/host回执后再验证域名/邮编、MCP鉴权/额度和Rufus/Alexa入口。
5. 如默认打开 Sorftime 官网进行关键词挖掘，立即停止：这表示任务仍读取旧包/旧路由或角色绑定错误。刷新当前注册表与角色包后重新预检。
6. 本次治理修改涉及站点、Skill、来源路由和 Schema；下一次用于能力验收的 `test-validation` 必须使用 `full-regression`。机械检查通过不等于业务 P1。
