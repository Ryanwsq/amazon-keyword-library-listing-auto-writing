# 跨电脑首启与本地统一入口

本文件只管理安装、路径、外部能力与可用状态，不替代两个项目的AGENTS、Skill、业务判断边界或人工门。README中的来源优先级摘要以相应拥有合同为准。

## 一个仓库，不复制本机身份

统一克隆总仓；关键词入口为`projects/amazon-keyword-library`，Listing入口为`projects/amazon-listing-pipeline`。所有任务都应从这份代码或它的受控Git工作树取版本，不再维护另一份独立Listing代码副本。

应用侧栏中的“已保存项目”、现有任务的cwd和浏览器会话不会被Git自动修改。文件合并不等于任务绑定迁移。旧入口只保留历史资料，后续业务不得误从旧目录启动。无法通过当前客户端安全迁移绑定时，先报告需要用户调整的入口，不能手工篡改应用内部数据库或虚构已迁移。

旧输入、真实工作簿、历史Run、任务记录和登录信息保留在原本机位置。新电脑需要使用某份历史词库时，必须另行获准传输、核对来源与哈希、执行既有复用规则；干净克隆不含这些私有文件，也不能自动补造。

## 首次启动顺序

1. 克隆后在总仓根运行README中的环境预检及统一校验。Python预检只探测本机运行时，不访问提供商、不读密钥。Windows使用短目录，避免将总仓放进深层同步盘路径；不能移动单个角色包文件来缩短路径。
2. 在执行任务的环境中准备可用的表格生成、重新加载、公式检查和渲染能力。部署不能删除渲染、隐私、哈希或人口检查来“适配”缺少依赖的电脑。`unzip`是现有装配审计脚本的真实外部依赖；预检失败时先安装兼容版本，不能仅用7-Zip图形界面存在来代替命令兼容性。
3. 关键词主任务完整读取其项目AGENTS与必读资料；按`docs/thread-architecture.md`和`docs/thread-roles.md`绑定长期角色。参照该项目`docs/thread-map.local.example.md`，真实ID、host、cwd和本机授权只保存在被忽略的本机映射中。
4. Listing先读取`task-packages/registry.json`，以角色、版本、包路径和manifest哈希明确绑定；依次完整读包内`AGENTS.md`、`Agent.md`、`LOAD_ORDER.md`与直接依赖。注册表里的冻结发布标签是历史封包属性，不是当前GitHub在线状态；不为安装就改冻结包的哈希或业务内容。不能把`dependencies/skills/`注册成额外执行角色。
5. 按README准备网站账号、MCP及浏览器能力，在实际拥有任务中预检。特别分离Amazon联想的未登录环境与Alexa的认证环境。Windows上的浏览器备用只在各模块原有合同允许的范围使用，不跨模块扩大备用权限。
6. 新Run前重新锁定当前Git revision、规则拥有文件哈希、当前三组输入、产品事实和输出目录，校验角色/任务/cwd。跨项目沿用现有交接合同、双Run与来源哈希、正式回执和Listing主任务READY权限。旧事实不得覆盖新事实，旧任务ID不得复制成当前身份。

## 环境检查的含义

- `check_environment.py`：Python、Git、Node、ZIP命令兼容性和公开文件的Windows路径风险；不安装、不修复、不读账号配置。ZIP探针只在系统临时目录生成并删除合成样本，不读取用户工作簿。
- `validate_projects.py`：精确发布清单、22个权威Skill、两个项目原有结构/依赖/角色包检查。源文件缺失、多出未审查文件或字节漂移都失败，不能重新封存哈希来绕过。
- 明确忽略的本机绑定、`.codex/`、`.env*`及系统生成的`.DS_Store`/`Thumbs.db`不是发布输入；检查器不读取它们，也禁止将它们登记进发布清单。其他未审查业务文件仍失败。已获准发布的模板仍按原始哈希核验，不按扩展名跳过。
- 这两项通过仅证明所覆盖的本机机械条件；不证明网页登录、MCP剩余额度、Alexa可访问、业务语义正确或P1。
- Mac上的`core.autocrlf=true`干净克隆只是Windows换行配置模拟，不是Windows全流程实测。真实Windows环境须另行通过安装预检、浏览器/表格能力检查及获准业务验证。

## 后续更新

先检查当前工作树有无未提交修改或运行中任务；有则先保全并协调，不自动覆盖。更新日常`main`只允许快进，之后重新运行两项检查，并在新Run开始前刷新版本锁。原始Run和冻结成果不可就地改写；本次根级部署补充不改变任何业务Skill或判断边界。
