# SIF competitor source contract

## Input lock

- `Run_ID`、站点、获准竞品清单和本机忽略输出目录必须锁定。
- 每个竞品单独查询；父体无数据时只记录问题并由主任务决定是否补充获准子体。
- 查询口径固定最近30天，请求已确认的每 ASIN 300条适配器上限。
- 首选SIF MCP；不可用时允许同一SIF提供商的网页浏览器入口。网页不是来源替代，必须保持相同站点、ASIN、周期、上限和七列业务口径。

## Persisted response

每次MCP调用至少保存：来源记录 ID、批次、竞品 ASIN、站点、入口类型、全部请求参数、查询窗口、返回日期字段、数据截止日、抓取时间、返回行数、原始响应指针和完整返回。网页入口至少保存同一身份字段、查询条件、页面/导出原始证据、可见结果顺序和数量闭环。来源不返回准确起始日时写`来源未返回`；不能宣称来源侧已缩减未提供的字段。

## Minimal workbook

七列明细固定为：`竞品ASIN`、`SIF返回序号`、`英文关键词`、`ABA排名`、`搜索量`、`Top3点击份额`、`Top3转化份额`。每个竞品返回记录均保留一行，不按相关性删除。核心词候选摘要可按机械键计算竞品覆盖数、最佳/中位返回序号和字段冲突，但不得确认一级品类核心大词、产品细分核心词、主执行锚点或强等价表达。高覆盖、高返回位置、高ABA或高搜索量只描述竞品流量证据，不表示产品对象等价或核心层级。

## Handoff

回传主任务：工作簿、Run相对路径、文件哈希、竞品清单与状态、逐竞品入口类型/返回行数、七列明细行数、核心词候选数、字段缺失/冲突、原始证据清单指针、异常和完成状态。原始业务响应正文只保留在 `.local/runs/<Run_ID>/keyword-sif-collector/`，不进入主任务消息。

## Gate

每个成功查询均有入口类型、完整原始证据、参数、时间、周期、行数和本机指针；七列工作簿与原始记录数量可回查；失败竞品有准确原因。入口间续跑必须证明相同查询身份且无遗漏/重复，否则新建批次从头查询受影响ASIN。任一证据未保存、站点/父子体不明、结构冲突或两个入口均不可用时回传`blocked/incomplete`，但不得抹去其他竞品已取得结果。
