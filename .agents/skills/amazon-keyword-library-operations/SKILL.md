# Amazon Keyword Library Operations

## 目标

锁定一次用户输入和运行版本，调度长期单一职责副任务，机械合并三来源，并控制各阶段汇合门、两对象最终交付和独立验收。

## 输入

用户产品事实和竞品、用户确认的目标Amazon类目及该类目是否存在多个稳定产品类型细分、Run_ID、仓库revision、站点、规则版本、获准本机目录，以及各副任务锁定工作簿和manifest。执行三来源合并时读取`references/source-merge-contract.md`。

## 输出

- 运行输入锁、并行任务路由、阶段状态和冲突清单。
- 第一板块两Sheet业务工作簿及本地manifest。
- 最终两个顶层交付对象的汇合状态。
- 独立QA结论和可回滚版本说明。

## 可调用能力

- `keyword.library.version.manage`
- `keyword.source.merge-and-assemble`

## 执行步骤

1. 读取项目知识索引、端到端流程、判断边界和本任务直接合同，锁定Run、revision、产品事实、竞品、站点、周期和全部规则版本。开头必须要求用户确认目标Amazon类目，以及该类目是否存在多个稳定产品类型细分；用户不负责指定任何核心词。
2. SIF副任务先行并正式回传。主任务结合锁定产品事实卡、直接竞品同对象身份和SIF候选，独立确认一个一级品类核心大词。只有用户确认目标类目存在多个稳定产品类型细分时，才可用同一证据发现、验证一个可选产品细分核心词；用户确认不存在时该字段必须留空。存在细分核心词时，主执行锚点必须等于该词；不存在时等于一级品类核心大词。另行锁定零至多个强等价表达、宽泛/相邻流量词及其证据层级。单独卖点、配置、配件、材质、尺寸、功能、容量、使用场景或高流量长词不能建立细分核心层级；流量只在同一语义层级内排序。
3. 锁定Amazon联想锚点和卖家精灵种子集合。存在已确认细分核心词时，Amazon联想锚点使用细分核心词，卖家精灵分别使用一级品类核心大词和细分核心词两个种子；不存在时，两者都只使用一级品类核心大词。强等价表达、宽泛/相邻流量词、卖点、配置和场景词不得默认成为额外种子；每个锚点/种子的层级、产品事实依据和SIF验证依据必须随输入锁传递。
4. 每次派发前先按被Git忽略的本机映射机械核对逻辑角色、固定任务标题、任务ID/host、执行cwd、Run_ID、revision和输出目录；任一不符时停止派发。身份门闭合后并行调度Amazon联想和卖家精灵扩词；来源副任务按各自入口优先级执行并记录入口类型、回退和完整性。等待SIF和两个分支全部正式回传；副任务只回传最小工作簿、manifest和紧凑状态。主任务不得因副任务不可用、未初始化、操作不便或已经看到证据而代跑来源模块，也不得用临时通用子代理替代固定长期副任务。
5. 按机械合同合并三来源全部已取得关键词。不得读取长响应正文做语义决定，也不得因流量或字段缺失删词。
6. 生成`Sheet1_关键词池`和`Sheet2_任务信息与类目锚点`；锚点区必须分别记录一级品类核心大词、可选细分核心词、主执行锚点、Amazon联想锚点、卖家精灵一至两个种子、强等价表达、宽泛/相邻流量词、各自证据和完整词覆盖边界。Amazon联想`not_executed`或任一必选来源未闭合时，只能标记第一板块不完整。
7. 路由第二板块清洗；清洗闭合后并行调度词频与分类；分类完成后并行调度竞争与趋势。每个模块必须由对应长期副任务执行并返回当前Run相对路径、哈希、人口、状态、缺口和验证。词频、竞争和趋势只使用清洗已判定`通用词库资格=纳入`的适用人口；趋势调度固定`SellerSprite -> Sorftime`优先级，并要求同一Run全部趋势人口只使用一个锁定提供商。
8. 等待所有适用分支并锁定哈希，路由最终装配生成`过程性文件/`和八Sheet最终工作簿；最终`二类词`Sheet必须机械复制分类完成的Sheet4全人口与固定十六列。
9. 路由独立质量验证执行21项门。QA未通过时不得把交付标记完成。
10. 正式只读Run中不修改知识或Skills；所有问题写同一个问题文档。整轮结束并经用户确认后，才进入获准迭代。只有用户在了解影响后明确授权的一次性Run例外，主任务才可接收已经产生但未由拥有副任务正式回传的证据；例外必须留痕，不得成为默认路由或P1证据。
11. 修改知识或Skill时同批同步端到端流程；发布前执行脱敏、结构、状态和Git检查。

## 质量标准

- 并行依赖和汇合门正确，任一分支未完成不会被默认完成。
- 三来源已取得词无语义删除，规范流量和Top3来源可追溯。
- SIF网页和Amazon联想普通Chrome只作为各自合同内备用入口；卖家精灵关键词挖掘以拥有副任务的已登录网页端及完整官方导出为首选，网页不可用时才切同提供商MCP。入口切换不改变提供商、查询或字段，无法闭环时状态准确降级。
- 趋势使用锁定来源优先级且单Run单一提供商；实际搜索量图与比例表格职责不混合。
- 第一板块只有两个业务Sheet，主键和人口闭合。
- 一级品类核心大词、可选细分核心词、主执行锚点、强等价表达和宽泛/相邻流量词没有混层；有细分核心词时主执行锚点与其一致，否则与一级品类核心大词一致。
- 卖家精灵种子集合严格服从“有细分核心词时一级核心词与细分核心词各一个，否则只有一级核心词”；Amazon联想锚点严格服从“有细分核心词时使用细分核心词，否则使用一级核心词”。高流量、竞品高排名或营销用途不能单独改变锚点或追加种子。
- 用户只确认目标类目与是否存在多个稳定产品类型细分；一级品类核心大词和条件允许时的细分核心词均由主任务依据事实卡与SIF证据独立判断。
- 所有执行模块都有拥有副任务的正式回传；一次性例外已获用户明确批准并保持可见，未被当作默认流程或能力证据。
- 清洗输出的`通用词库资格`能够向词频、竞争、趋势和最终通用词库传递，品类相关人口不会被自动等同为本产品强相关人口。
- 最终顶层只有两个对象，最终工作簿恰好八个可见Sheet；二类词独立Sheet与分类Sheet4人口和字段闭合。
- 状态准确；旧规则工作簿不冒充当前合同结果，draft/planned不冒充P1。

## 异常处理

输入、版本、哈希、主键或人口无法锁定时停止相应汇合。目标Amazon类目或多产品细分回答缺失，一级品类核心大词、条件允许时的可选细分核心词、主执行锚点、联想锚点、卖家精灵种子集合或确认依据无法闭合时，停止第一板块下游调度，不得以宽泛流量词顶替。固定任务身份门不闭合、拥有副任务未执行且没有用户明确的一次性Run例外时，报告受影响模块并等待，不由主任务代跑或临时替代。来源局部失败保留已取得结果并报告损失风险；Amazon联想未执行则正常案例不完成。业务判断冲突路由拥有Skill或用户，不由主任务自行改写规则。
