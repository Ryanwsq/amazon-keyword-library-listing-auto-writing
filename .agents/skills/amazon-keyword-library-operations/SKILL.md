# Amazon Keyword Library Operations

## 目标

锁定一次用户输入和运行版本，调度长期单一职责副任务，机械合并三来源，并控制各阶段汇合门与两对象最终交付；独立质量验证副任务只在明确的测试/回归验证Run中调度。

## 输入

用户开头一次性提交三项输入：产品基础信息配置、产品配置卖点、竞品对标ASIN。其中产品基础信息必须包含目标Amazon类目及该类目是否存在多个稳定产品类型细分。另锁定`run_type=production|test-validation`、Run_ID、revision、站点、规则版本、获准本机目录，以及各副任务工作簿和manifest；未明确为测试、回归、能力案例或P1评估时默认`production`。原始直接竞品ASIN超过5个时，必须先按稳定竞品产品类型分组，每类只保留输入顺序中的第一个有效ASIN，并锁定原始/入选/排除清单和理由。多细分类目还必须形成目标细分强等价闭环的候选、逐项结论和证据。执行三来源合并时读取`references/source-merge-contract.md`；执行性能、断点续跑和失败隔离另读取`../../../docs/runtime-optimization-contract.md`，该合同不得覆盖任何业务规则。

## 输出

- 运行输入锁、并行任务路由、阶段状态和冲突清单。
- 第一板块两Sheet业务工作簿及本地manifest。
- 最终两个顶层交付对象的汇合状态。
- production Run的装配自检/交付状态，或test-validation Run的compact/full独立QA结论和可回滚版本说明。

## 可调用能力

- `keyword.library.version.manage`
- `keyword.source.merge-and-assemble`
- `keyword.runtime.contract.manage`
- `keyword.runtime.failure-isolation.verify`

## 执行步骤

1. 读取项目知识索引、端到端流程、判断边界、本任务直接合同和运行优化合同，锁定run_type、Run、revision、站点、周期、全部规则版本及用户三项输入。目标Amazon类目和“是否存在多个稳定产品类型细分”必须包含在开头的产品基础信息中；若已提供不得再次询问，缺失时Run不得启动。用户不负责指定任何核心词。未明确为测试/回归/P1案例时run_type默认`production`。使用`scripts/runtime_contract.py`在本机Run目录生成并验证内容寻址运行合同；合同只锁定输入、规则拥有文件哈希、阶段键和执行器版本，不用规则摘要替代各Skill完整阅读。
2. 在调度SIF前闭合竞品人口。原始直接竞品ASIN不超过5个时全部保留；超过5个时按输入中可验证的稳定竞品产品类型分组，每类机械保留输入顺序中的第一个有效ASIN，记录其余排除项及`同类型代表已保留`理由。类型无法可靠确认，或每类取一后仍超过5个时，在任何SIF查询前停止并向用户升级，不能静默丢掉某一类型。筛选后的1–5个ASIN才是SIF获准清单；因每类只留一个而少于3个不构成额外补选理由。
3. SIF副任务先行并正式回传。主任务结合锁定产品事实卡、直接竞品同对象身份和SIF候选，独立确认一个一级品类核心大词。只有用户确认目标类目存在多个稳定产品类型细分时，才可用同一证据发现、验证一个可选产品细分核心词；用户确认不存在时该字段必须留空。存在细分核心词时，主执行锚点必须等于该词，并在继续调度前完成目标细分强等价闭环：逐项检查省略一级品类词、用途限定词或其他上位限定词后仍保留决定性细分表达和完整商品头部的候选，结合产品事实、直接竞品同对象身份及SIF覆盖/返回位置确认是否仍唯一交付目标细分。满足时锁定为强等价表达；缺少上位限定词本身不得写成宽泛/相邻。不存在细分核心词时主执行锚点等于一级品类核心大词，不启用该细分简称闭环。另行锁定零至多个宽泛/相邻流量词及其证据层级；同一机械键不得同时进入强等价和宽泛/相邻清单。单独卖点、配置、配件、材质、尺寸、功能、容量、使用场景或高流量长词不能建立细分核心层级；流量只在同一语义层级内排序。用户未逐项确认核心层级时，锚点来源不得写成`用户确认`。
4. 锁定Amazon联想锚点和卖家精灵种子集合。存在已确认细分核心词时，Amazon联想锚点使用细分核心词，卖家精灵分别使用一级品类核心大词和细分核心词两个种子；不存在时，两者都只使用一级品类核心大词。每个卖家精灵种子只允许一个成功完整结果，不做同种子交叉重复导出。强等价表达、宽泛/相邻流量词、卖点、配置和场景词不得默认成为额外种子；每个锚点/种子的层级、产品事实依据和SIF验证依据必须随输入锁传递。
5. 每次派发前先按被Git忽略的本机映射机械核对逻辑角色、固定任务标题、任务ID/host、执行cwd、Run_ID、revision和输出目录；任一不符时停止派发。Run开始时可并行预检SIF与卖家精灵登录并只写无凭据preflight状态；两个副任务仍必须在首次官网业务动作前核对该状态。未登录时副任务只回传`awaiting_login`，由主任务提示用户登录并冻结对应分支，登录恢复后继续。未登录不得直接触发MCP。身份门闭合后并行调度Amazon联想和卖家精灵扩词；来源副任务按各自入口优先级执行并记录入口类型、回退和完整性。等待SIF和两个分支全部正式回传；副任务只回传最小工作簿、manifest和紧凑状态。主任务不得因副任务不可用、未初始化、操作不便或已经看到证据而代跑来源模块，也不得用临时通用子代理替代固定长期副任务。
6. 按机械合同合并三来源全部已取得关键词。不得读取长响应正文做语义决定，也不得因流量或字段缺失删词。合并后用`scripts/keyword_deterministic_core.py validate-source-merge`全量核对来源机械键并集、重复人口和来源身份；它不选择指标、不删除词，也不执行核心词或相关性判断。
7. 生成`Sheet1_关键词池`和`Sheet2_任务信息与类目锚点`；任务摘要必须记录原始/入选/排除ASIN及代表选择理由。锚点区必须分别记录一级品类核心大词、可选细分核心词、主执行锚点、Amazon联想锚点、卖家精灵一至两个种子、强等价表达、宽泛/相邻流量词、各自证据、目标细分强等价闭环状态和完整词覆盖边界。多细分类目中，SIF候选摘要及直接竞品高相关表达里的简称/紧凑写法必须逐项落入强等价、宽泛/相邻或未确认候选之一，并通过层级冲突检查。Amazon联想`not_executed`、任一必选来源未闭合或强等价闭环未闭合时，只能标记第一板块不完整。
8. 路由第二板块清洗；清洗闭合后并行调度词频与分类；分类完成后并行调度竞争与趋势。每个模块必须由对应长期副任务执行并返回当前Run相对路径、哈希、人口、状态、缺口和验证。每个完成阶段写入匹配运行合同的stage status；只有stage key、输出/证据哈希、人口和状态全部闭合才可断点复用。阶段失败只阻断该阶段后代：词频失败不得暂停分类、竞争或趋势，分类失败不得推翻已完成词频；最终装配仍等待全部适用分支。词频、竞争和趋势只使用清洗已判定`通用词库资格=纳入`的适用人口；趋势调度固定`SellerSprite -> Sorftime`优先级，并要求同一Run全部趋势人口只使用一个锁定提供商。
9. 等待所有适用分支并锁定哈希，路由最终装配生成`过程性文件/`和八Sheet最终工作簿；最终`二类词`Sheet必须机械复制分类完成的Sheet4全人口与固定十六列。production Run由装配任务执行全部机械、人口、公式、图表、渲染、隐私和哈希检查后直接交付，不调度独立质量验证副任务；21个Gate ID保留，独立QA专属Gate写`not_applicable`，不得伪写QA pass或P1。
10. 只有`run_type=test-validation`时才路由独立质量验证副任务。普通测试可使用compact验证档；规则/Skill/Schema/公式/图表/封包/检查器变化、两个正常加一个边界案例或P1评估必须使用`full-regression`。测试Run中QA未通过不得把该测试交付标记完成。历史`compact-production`仅作为冻结旧Run标识，不再用于production路由。
11. 正式只读Run中不修改知识或Skills；所有问题写同一个问题文档。整轮结束并经用户确认后，才进入获准迭代。只有用户在了解影响后明确授权的一次性Run例外，主任务才可接收已经产生但未由拥有副任务正式回传的证据；例外必须留痕，不得成为默认路由或P1证据。
12. 修改知识或Skill时同批同步端到端流程；发布前执行脱敏、结构、状态和Git检查。

## 质量标准

- 并行依赖和汇合门正确，任一分支未完成不会被默认完成。
- 运行合同可从当前权威文件复算，未变化阶段只在stage key、输出/证据哈希及人口完全一致时复用；规则或输入漂移只重跑受影响阶段及后代，不冻结无关分支。
- 三来源已取得词无语义删除，规范流量和Top3来源可追溯。
- SIF和卖家精灵均由拥有副任务在首次官网业务动作前验证登录；未登录只回传主任务`awaiting_login`，由主任务提示用户并冻结分支，不能直接切MCP。Amazon联想普通Chrome只作为合同内备用入口；卖家精灵每个种子只保存一个成功完整官方导出，已登录但网页不可用时才切同提供商MCP。入口切换不改变提供商、查询或字段，无法闭环时状态准确降级。
- 趋势使用锁定来源优先级且单Run单一提供商；实际搜索量图与比例表格职责不混合。
- 第一板块只有两个业务Sheet，主键和人口闭合。
- 一级品类核心大词、可选细分核心词、主执行锚点、强等价表达和宽泛/相邻流量词没有混层；有细分核心词时主执行锚点与其一致，否则与一级品类核心大词一致。
- 多细分类目已完成目标细分强等价闭环；省略上位限定词但仍保留决定性细分表达与完整商品头部的候选已按组合证据逐项判断，不以缺少一级品类/用途token作为宽泛或摘除依据。同一机械键零层级冲突，用户未实际逐项确认的核心层级未伪标为`用户确认`。
- 卖家精灵种子集合严格服从“有细分核心词时一级核心词与细分核心词各一个，否则只有一级核心词”；Amazon联想锚点严格服从“有细分核心词时使用细分核心词，否则使用一级核心词”。高流量、竞品高排名或营销用途不能单独改变锚点或追加种子。
- 原始直接竞品ASIN超过5个时按稳定产品类型每类只保留输入顺序中的第一个有效ASIN；原始、入选、排除人口闭合，类型不明或每类取一后仍超过5个时没有静默删词或外部查询。
- 用户在开头的产品基础信息中只确认目标类目与是否存在多个稳定产品类型细分；一级品类核心大词和条件允许时的细分核心词均由主任务依据事实卡与SIF证据独立判断。Run启动后不再次请求业务确认。
- 所有执行模块都有拥有副任务的正式回传；一次性例外已获用户明确批准并保持可见，未被当作默认流程或能力证据。
- 清洗输出的`通用词库资格`能够向词频、竞争、趋势和最终通用词库传递，品类相关人口不会被自动等同为本产品强相关人口。
- 最终顶层只有两个对象，最终工作簿恰好八个可见Sheet；二类词独立Sheet与分类Sheet4人口和字段闭合。
- run_type路由准确：production不派发独立质量验证且独立QA专属Gate为`not_applicable`；test-validation才允许派发，规则或检查器变化/P1案例使用full regression。
- 状态准确；三种行级数据缺口自动对应`completed_with_gaps`而不等待用户；旧规则工作簿不冒充当前合同结果，draft/planned不冒充P1。

## 异常处理

输入、版本、哈希、主键或人口无法锁定时停止相应汇合。目标Amazon类目或多产品细分回答未包含在开头产品基础信息中时Run不启动；一级品类核心大词、条件允许时的可选细分核心词、主执行锚点、联想锚点、卖家精灵种子集合或确认依据无法闭合时，停止第一板块下游调度，不得以宽泛流量词顶替。多细分类目的目标细分强等价闭环未完成、同一机械键落入冲突层级，或候选仅因缺少一级品类/用途token被写成宽泛/相邻时同样停止。固定任务身份门不闭合或拥有副任务未执行时报告受影响模块，不由主任务代跑或临时替代。来源局部失败保留已取得结果并报告损失风险；Amazon联想未执行则正常案例不完成。运行中业务歧义由拥有Skill按保守去向/缺口状态处理或准确阻断，不向用户请求判断；只有获准网页入口需要新登录时进入`awaiting_login`。
