# Amazon Keyword Quality Validation

## 目标

对锁定Run执行独立只读验收，验证全链路、两个顶层对象、八Sheet最终工作簿和21项装配门，输出可追溯结论而不修复上游。

## 输入

Run_ID、仓库revision、站点、用户确认的目标类目多稳定产品类型输入门、一级/细分核心词、来源锚点与种子、全部模块版本、过程文件夹、八Sheet最终工作簿、process manifest、上游manifests、唯一问题文档和获准质量目录。

## 输出

- `独立质量验证.xlsx`：固定两个Sheet，每个QA尝试只生成一次。
- `quality-manifest.json`。
- 最终八Sheet必要预览、同一问题文档和唯一引用；整套QA产物生成后不可改写。
- QA结论`pass/blocked/incomplete`和交付状态。

## 可调用能力

- `keyword.quality.validate`

## 执行步骤

1. 读取知识、判断边界和`references/quality-contract.md`；锁定Run/revision、版本、哈希、用户对“类目是否存在多个稳定产品类型细分”的回答和产物清单。
2. 只读验证三来源状态、获准入口类型与回退证据、第一板块两Sheet、机械词池和损失风险。有细分核心词时，Amazon联想必须以细分核心词为锚点，卖家精灵必须分别以一级品类核心大词和细分核心词执行两个种子，每个种子都有官网完整官方导出优先的版本化Pass证据，并在卖家精灵模块内按机械键去重且保留双种子来源；无细分核心词时，Amazon联想和卖家精灵都只使用一级品类核心大词。
3. 验证第二板块四Sheet、三去向、主键、理由和人口闭环；核对一级品类核心大词、可选细分核心词、主执行锚点、强等价表达和宽泛/相邻流量词没有混层。语义反向抽查不能只找误纳：必须从Sheet2`通用词库资格=不纳入`、Sheet3和Sheet4反查假阴性，覆盖一级核心商品加普通属性、材质、结构、功能、配置，以及未显式包含细分核心词但完整表达仍为同一中心商品的词。不得把缺少细分核心词字面或目标SKU不具备某配置作为不纳入依据；只有用户已确认类目存在多个稳定产品类型细分，且完整词确实表达同类目另一稳定产品类型时，才接受二类词判定。
4. 验证分类两Sheet、N动态列、F1–F5、F5主分组/LT和五列否词库；核对`关键词ABA排名缺失、搜索量缺失、没有搜索量`的状态、原始值和派生留空是否符合合同。
5. 验证词频、竞争和趋势均只使用`通用词库资格=纳入`的适用人口，再验证词频固定介词删除/断点、竞争十二列与Top3矩阵、趋势来源优先级/单一提供商、24月/两矩阵/两张实际搜索量图。
6. 验证最终总表三去向51+N、SKU事实、通用词库按品类相关且资格纳入机械筛选、五个流量块显示表头、最终`二类词`与分类Sheet4人口/十六列/主键/值一致、独立四个分析Sheet及八Sheet顺序。
7. 执行过程文件哈希/敏感信息检查和21项装配门；每个失败Gate引用唯一问题文档中的同一根因问题ID。当前有效最终合同固定为八Sheet；七Sheet只可在明确标记`superseded`的历史证据语境中出现，不能通过当前Gate。
8. 为最终八Sheet各生成至少一个可复核预览；趋势图单独核对序列和范围。
9. 在获准质量目录一次性写入两Sheet质量工作簿、最小quality manifest、同一脱敏问题文档与唯一引用、必要预览；对三种行级数据状态生成去重用户确认清单并回传主任务。生成后整套QA产物及其哈希不可改写。用户确认未闭合时结论为`incomplete`，不写`blocked`；若用户要求改值，返回分类拥有副任务后重新装配并开始新的QA尝试，当前QA不直接修改。
10. 最终装配完成封包并生成唯一process manifest后，只执行只读包装差异核对：验证质量目录白名单、manifest自身以外的全部最终文件均在唯一process manifest中恰好一条且路径/大小/哈希一致、装配与QA隐私扫描交叉结果一致，并重核Gate 19–21。此阶段不得新增、覆盖或重写质量工作簿、quality manifest、预览、问题文档或引用；发现差异只回传状态、根因、所有者和建议，不修文件。硬门失败不得输出pass。

## 质量标准

- 对上游和最终封包全程只读，不调用业务外部系统、不重跑、不修改上游、不改规则；只允许在首次生成阶段写入合同白名单内的QA产物。
- Gate状态只用`pass/fail/not_executed/not_applicable`。
- 来源锚点审计以用户类目多稳定类型输入门为前提：有细分时联想使用细分核心词、卖家精灵保留一级核心词与细分核心词两个种子的独立官方导出/Pass血缘；无细分时两者使用一级核心词。
- 锚点与清洗语义审计覆盖全部一级品类核心大词、细分核心词、强等价表达、当前输入门要求的一个或两个卖家精灵种子、SIF候选摘要头部词及最终通用词库高流量词；同时从Sheet2不纳入、Sheet3和Sheet4反查假阴性。流量、竞品排名、缺少细分核心词字面、营销用途或目标SKU配置均不能单独通过或否决核心层级、品类去向或通用词库资格。
- 合同允许缺口可为QA pass且交付completed_with_gaps；硬门失败只能blocked/incomplete。
- 三种行级数据状态不是分类整批停止门；未得到用户最终确认前QA为`incomplete`，用户接受其实际状态后可作为合同允许缺口评估。
- 同一根因只在唯一问题文档记录一次，多个Gate复用问题ID。
- 质量目录严格使用合同白名单，不复制接口正文、整张关键词表或上游工作簿；QA产物只生成一次，最终封包后只读核对、不再写入。
- 当前正式交付只接受八Sheet；七Sheet仅可作为明确`superseded`的历史证据。
- Skill保持draft/planned，P0不冒充P1。

## 异常处理

缺少revision、manifest、必需产物、哈希、用户类目多稳定类型输入门、来源锚点/种子及官方导出/Pass血缘、通用词库资格人口、二类词Sheet闭环或预览时结论`incomplete`。已执行检查发现硬门失败为`blocked`。只有待用户确认的`关键词ABA排名缺失、搜索量缺失、没有搜索量`时结论为`incomplete`而不是`blocked`。最终封包后的差异若源于缺少材料/检查则为`incomplete`，已确认路径/大小/哈希、白名单、隐私或Gate 19–21失败则为`blocked`；不得通过改写既有QA产物闭合。质量任务只报告所有者和建议下一步，不直接修复。
