# Recent final-library reuse contract

## Scope and ownership

这是用户于2026-09-03确认的常规入口，不再要求逐Run申请一次性复用例外。稳定定义见`../../../../knowledge/product-keyword-library.md`的“近30天最终词库复用”，判断门见`../../../../docs/keyword-judgment-boundaries.md`的同名章节。主任务负责资格与新事实锁定；最终装配长期副任务负责副本换卡、等值检查和交付。不得由主任务代装配，也不新增来源或临时任务。

`execution_mode=fresh-collection|recent-library-reuse`与`run_type=production|test-validation`是两条独立维度。三组开头输入及类目/多细分必填门不变。先检查可用历史最终工作簿，满足本合同才走`recent-library-reuse`；否则记录原因并走原`fresh-collection`全流程，不为寻找可复用文件无限扫描历史运行。

## Reuse eligibility

1. 新产品与历史词库**已经判定的**Amazon类目相同，站点相同。主任务以新输入中的类目与完整中心商品，对照历史类目锚点及判定证据；不能只看文件名、共享词根或标题中的营销用途。
2. 类目无多个稳定产品类型细分时，不判断细分，细分核心词留空。存在细分时，必须证明新产品与历史词库指向同一稳定产品类型；主任务用新事实和历史事实/直接竞品同对象身份/SIF锚点证据核对，无须先重新采集SIF。细分未确认、两边细分存在性冲突或类型不同，不能用空值相等放行。核心词及细分词仍由主任务判断，不让用户指定。普通材质、尺寸、功能、卖点和配置差异不自行构成另一细分。
3. 历史最终工作簿的可追溯原始输出时间距本次检查为`0 <= age <= 30天`，边界含第30天。用有时区的输出/交付记录计算，不用下载时间、复制时间、修改时间或文件名猜测。源文件若已是复用副本，沿血缘追溯产生该关键词库的原始最终输出时间；换卡/改名/再次输出不得重置30天。装配封口前再核对此期限。

以上条件齐全即可直接复用，无须因新SKU配置不同重跑来源、清洗、分类、词频、竞争或趋势。未知/过期/不同类目或细分时只拒绝复用入口；原输入完整则继续原流程，不新增运行中人工确认门。

源文件必须真实可读，SHA-256、八Sheet、人口、已判定锚点和必要过程血缘可核对；源版本与当前适用业务边界不冲突。旧revision不必与新revision相等，不能把规则文件因本次新增入口而变哈希直接等同为业务不兼容；但已知错误、已废弃判断或不符合当前输出结构不能因“30天内”变成有效。无需把旧Skill成熟度或未执行独立QA升级为通过；旧允许缺口/QA未执行仍按原状态保留。

历史访问入口、导出次数及执行顺序按其源版本核验，不追溯套用当前新采集SOP从而强制重采；来源身份、指标含义、中心对象/语义判断和当前输出硬门仍须可核对且无冲突。新输入中尚未查询的竞品只作为本次输入保存，不替换历史已查询ASIN。

## Lock before dispatch

主任务在新Run忽略目录建立`reuse-contract.json`，使用schema `amazon-keyword-recent-library-reuse/v1`，至少锁定：

- `execution_mode、run_id、run_type、revision、site`；test-validation还锁定qa_mode与变更触发项。
- 当前三项输入各自SHA-256、新SKU事实卡相对指针/SHA-256、当前类目和多细分回答。
- 历史`source_run_id、source_revision、source_workbook`相对指针/SHA-256、原始最终输出时间及其证据指针、来源数据周期、源规则版本、必要源manifest/锚点/人口哈希；链式复用同时锁定直接父本与最初来源。
- 新旧类目/条件式细分对照、主任务结论及证据指针、检查时间与age、兼容性结论、历史缺口与质量状态、`p1=false`。
- 新旧事实隔离、七个非事实Sheet等值范围、输出目录、装配执行器版本、规则拥有文件哈希；适用依赖仅为`reuse-eligibility -> assembly`，test-validation再接`quality-validation`。未执行的上游标`execution=not_executed、data_origin=historical_reuse`，另保留其source原状态；不得伪造本Run的上游`completed`。

合同规范化为UTF-8、键排序、无多余空白的JSON后计算SHA-256，自身哈希记在合同外的dispatch/manifest，禁止自哈希循环。至少锁定本Skill/本合同、稳定知识、判断边界及装配Skill/合同；测试再锁定QA Skill/合同。写入前核对合同、当前三项输入/新事实卡、全部引用源文件及规则拥有文件哈希，任何漂移停止换卡并重新锁定，不静默更新。

这是独立的内容寻址复用合同，不把它伪装成`amazon-keyword-run-contract/v1`。当前`scripts/runtime_contract.py build/verify/ready/resume`仅用于fresh-collection及该流程的同Run续跑；复用分支由主任务和装配逐项核对本合同，不调用旧脚本强求全量上游ready，不放宽旧脚本的精确匹配门。真实任务ID、机器路径、会话只留本机映射，不进入合同或交付。

## Fact replacement and unchanged library

- 原工作簿与历史过程证据只读保留；生成新Run的新副本。新`SKU事实卡`四列全量来自当前锁定输入，新ASIN、品牌、型号、尺寸、配置、卖点及缺失状态不得沿用旧卡补齐。历史卡只作判定血缘，不能作为当前事实来源。
- 另外七个Sheet保持关键词人口、Keyword_ID、原文、指标、来源周期、源规则版本、三去向、资格、分类、否词、词频、竞争、趋势、公式和图表不变；只允许必要的当前交付身份/装配版本/血缘说明变化，并逐字段列明白名单与前后值。不得把`采集批次`改为新Run，也不得把趋势“最近月/季”改成今天对应期间而不更新数据。
- 关键词中出现历史品牌是来源文本，不是事实污染；不得全工作簿搜索替换旧品牌或ASIN。品牌变化本身不禁止复用，但若原自有品牌/授权裁决会被错误当作新产品授权，或旧SKU专属理由与新事实冲突，则直接复用不能静默通过：回主任务按已有判断边界选择正常流程或另行获准的有界修订，不在装配改语义。
- 新过程目录按原四分区保留必要历史证据并明确标为历史来源，当前输入/换卡说明另标当前Run；源事实在历史证据中不覆盖、不冒充当前。源质量文件只作历史证据，不能放入新Run质量目录冒充当前QA；新manifest记录source状态、新事实哈希、复用合同哈希和新输出哈希。

## Acceptance

装配重新检查八Sheet、两对象、七Sheet等值、事实卡新输入一致、人口/主键、公式/图表、渲染、隐私与哈希；Gate 1–20保留，Gate 2/10/19明确区分历史source锁与当前fact/output锁，不以两者Run或revision不同机械报污染。新输入无关的历史来源ASIN不得改写成当前已反查竞品。

独立QA仍只由run_type决定：production不派发，Gate 21=`not_applicable`；test-validation按现有compact/full触发规则执行，变更后的复用验证使用full。历史QA通过、人工接受或30天资格都不是本次QA通过；取消/未执行不改写成通过。源数据缺口与源质量状态继续可见，新交付状态只依据本次适用检查。复用未实际执行的模块不产生新案例或P1。
