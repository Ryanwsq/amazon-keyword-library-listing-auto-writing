# SIF competitor source contract

## Input lock

- `Run_ID`、`marketplace`、提供商查询站点参数、原始竞品清单、竞品产品类型映射、最终获准竞品清单、排除清单/理由和本机忽略输出目录必须锁定。`marketplace`只允许`Amazon-US`或`Amazon-DE`，提供商参数必须与Run站点一致；不一致时记录`marketplace_mismatch`、停止并通知用户介入，不得静默改成US。原始竞品不超过5个时全部保留；超过5个时按稳定竞品产品类型分组，每类机械保留输入顺序中的第一个有效ASIN。类型无法可靠确认，或每类取一后仍超过5个时，必须在查询前回传主任务阻断，不得自行丢弃某一类型。
- 每个竞品单独查询；父体无数据时只记录问题并由主任务决定是否补充获准子体。
- 查询口径固定最近30天，请求已确认的每 ASIN 300条适配器上限。
- 首选长期副任务内置浏览器中的已登录SIF官网网页端。每个Run在第一次查询前验证登录状态；未登录时进入`awaiting_login`，暂停并只回传主任务，由主任务提示用户登录，不得由副任务直接向用户发问，也不得仅因当前未登录而切换MCP。
- 仅当用户明确无法完成SIF网页登录，或已登录但完整官网导出失败，并取得本Run用户批准且同提供商MCP已鉴权时，才允许同一提供商的SIF MCP作为备用。入口切换必须保持相同站点、ASIN、最近30天周期、300条上限、七列业务字段、结果顺序和数量闭环。

## Persisted response

### 已登录但完整导出失败的同提供商备用

完整官网导出生成、下载或落盘失败，与未登录/零关键词分别记录。保存可见失败证据后回传主任务；有当前Run用户批准和同提供商MCP鉴权证据才可备用，不能因为等待时间长或未登录自动跳过网页。新派发在`admission.query_lock`冻结Run、站点、全部获准ASIN、最近30天、过滤条件（无附加过滤显式写空对象）和300条上限；备用另冻结原因/用户批准/鉴权证据。查询锁格式与入口见`../../../../docs/dispatch-control-contract.md`。

`../../../../scripts/source_execution.py sif-fallback --input <本机证据.json>`验证备用原因、证据文件哈希和鉴权证明内容；输入含`run_id、task_id、host、source_provider=SIF、reason=user_cannot_login|authenticated_export_failed、user_approved、mcp_authenticated`和`authorization、failure_evidence、authentication_evidence`三个`path/sha256`指针。导出失败分支另含`web_authenticated=true`。鉴权文件必须使用下方非敏感结构，Run/Task/host与proof完全一致；dispatch接收还把proof的task_id/host与envelope目标thread_id/host核对。不能将其他任务的鉴权文件包装成当前任务证明，不接受仅有hash或authenticated布尔自报。原始凭据、Cookie、令牌或其他未列字段禁止进入证明；可附非敏感checked_at。拥有任务仍须核对实际鉴权和用户批准真实性，保留站点/ASIN/周期/七列/300条及完整性；这些机械绑定不是全局权限判定或持续登录保证，不以脚本结果冒充业务完成。

```json
{
  "schema": "amazon-keyword-mcp-authentication/v1",
  "run_id": "AKW-SYNTHETIC-01",
  "task_id": "synthetic-task",
  "host": "local",
  "provider": "SIF",
  "entry_type": "mcp",
  "authenticated": true
}
```

以上仅字段示例，不是可执行鉴权证明；真实当前身份只写本机忽略文件。

### 一次已自动填充登录恢复

本任务此前已通过认证、随后跳回同一提供商登录页，且密码管理器已经填满账号和密码框时，允许只点击一次Login并重新核验提供商、账户身份、站点和查询锁。只观察非敏感的“已填充/未填充”状态，绝不读取、显示、复制、导出、记录、修改或补填凭据；无法不读取值而确认填充状态时，交用户。空白或部分填充、验证码/MFA、失败、错账户/站点、再次跳转都保持`awaiting_login`并由主任务引导用户。Amazon仍由用户登录。可用`source_execution.py login-recovery`验证仅布尔观察字段和一次尝试预算；它不点击界面，不生成登录完成回执。

每次网页查询至少保存：来源记录 ID、批次、竞品 ASIN、站点、入口类型、登录验证状态、查询条件、查询窗口、数据截止日、抓取时间、返回行数、完整页面/官方导出原始证据指针、可见结果顺序和数量闭环。获准备用的每次MCP调用至少保存同一身份字段、MCP启用依据、全部请求参数、返回日期字段、原始响应指针和完整返回。来源不返回准确起始日时写`来源未返回`；不能宣称来源侧已缩减未提供的字段。任何入口的原始证据均须先保存再解析，保存失败立即停止受影响查询。

## Minimal workbook

七列明细固定为：`竞品ASIN`、`SIF返回序号`、`英文关键词`、`ABA排名`、`搜索量`、`Top3点击份额`、`Top3转化份额`。每个竞品返回记录均保留一行，不按相关性删除。核心词候选摘要可按机械键计算竞品覆盖数、最佳/中位返回序号和字段冲突，但不得确认一级品类核心大词、产品细分核心词、主执行锚点或强等价表达。高覆盖、高返回位置、高ABA或高搜索量只描述竞品流量证据，不表示产品对象等价或核心层级。

## Handoff

回传主任务：工作簿、Run相对路径、文件哈希、原始/入选/排除竞品清单、逐ASIN产品类型和排除理由、逐竞品入口类型/返回行数、七列明细行数、核心词候选数、字段缺失/冲突、原始证据清单指针、异常和完成状态。未登录时先单独回传`awaiting_login`，不在副任务直接向用户发问。原始业务响应正文只保留在 `.local/runs/<Run_ID>/keyword-sif-collector/`，不进入主任务消息。

## Gate

原始/入选/排除ASIN人口先闭合；超过5个时每类只保留输入顺序中的第一个有效ASIN。每个成功查询均有入口类型、完整原始证据、参数、时间、周期、行数和本机指针；七列工作簿与原始记录数量可回查；失败竞品有准确原因。未登录时只向主任务回传`awaiting_login`并暂停，仅在无法网页登录或已登录但完整官网导出失败、本Run用户批准及MCP鉴权均闭合后才可启用MCP。入口间续跑必须证明相同查询身份且无遗漏/重复，不得把网页与MCP混成无身份续采；无法证明时新建批次从头查询受影响ASIN。ASIN类型无法确认、每类取一后仍超过5个、任一证据未保存、站点/父子体不明、结构冲突、首选网页不可执行且MCP启用条件未满足时回传`blocked/incomplete`，但不得抹去其他竞品已取得结果。
