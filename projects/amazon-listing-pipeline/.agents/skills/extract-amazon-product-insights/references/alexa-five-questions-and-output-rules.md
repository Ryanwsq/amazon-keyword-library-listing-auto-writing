# Alexa ASIN 五参数双问：问题、并集与 Excel 输出规则

## 1. 固定问题

每个合法 ASIN 使用以下五个问题。每题必须在两个相互独立的干净上下文中原样提交两遍；A 与 B 的唯一差异是执行实例，问题文本完全相同。

### Q1｜用途

    What would someone mainly use Amazon item {ASIN} to do?

执行记录：Q1A、Q1B。

只提取商品帮助用户完成的任务、行为或结果。地点、环境、人群和功能名称本身不属于用途。

### Q2｜场景

    In what situations or settings would someone normally use Amazon item {ASIN}?

执行记录：Q2A、Q2B。

只提取地点、环境、活动、时机或日常使用情境。没有情境信息的任务描述不作为场景。

### Q3｜人群

    Who would Amazon item {ASIN} be a good fit for?

执行记录：Q3A、Q3B。

只提取 Alexa 明确说明的适用购物者或使用者。不得根据品类刻板印象或模型常识推断年龄、性别、职业、健康状态或其他敏感属性。

### Q4｜特点（独特优势）

    What, if anything, makes Amazon item {ASIN} stand out from a basic product of the same type?

执行记录：Q4A、Q4B。

只提取 Alexa 明确说明的突出或差异化特点及其价值。What, if anything 不预设商品一定具有优势。

### Q5｜痛点（产品限制/用户反馈）

    What drawbacks or customer complaints, if any, are known for Amazon item {ASIN}? If Alexa does not have enough information, please say so rather than guessing.

执行记录：Q5A、Q5B。

只提取 Alexa 明确归因于目标商品的缺点、限制、客户投诉或客户反馈问题。if any 不预设一定存在痛点；信息不足时不得推测。

## 2. 双问隔离

- 固定顺序：Q1A、Q1B、Q2A、Q2B、Q3A、Q3B、Q4A、Q4B、Q5A、Q5B。
- 每次执行使用新的或完全无前题答案污染的上下文。
- B 不得看到 A 的回答、摘要、关键词或状态。
- 同一组 A/B 的问题文本必须逐字符一致，仅将 {ASIN} 替换成同一个规范化 ASIN。
- 不得准备改写问题，不得追加第三问，不得澄清或追问。
- 不得因为某次回答更短、无信息或答非所问而补问。
- 不得重复执行来挑选更完整或更有利的两次结果。

双问的目的为扩大覆盖并保留来源差异；单边事实只要身份可信且属于当前字段，就进入最终并集。

## 3. 内部记录

每个 ASIN、每个问题实例至少保留：

    input_asin
    normalized_asin
    marketplace
    language
    question_id
    run_id                  A | B
    field_name
    question_text
    question_character_count
    submitted_at
    alexa_raw_answer
    identity_binding_status
    normalized_facts[]
    technical_status
    evidence_locator

每个字段另保留：

    facts_a[]
    facts_b[]
    union_facts[]
    facts_in_both[]
    only_in_a[]
    only_in_b[]
    conflicting_facts[]
    union_status

原始记录用于审计，业务主表只使用 union_facts[]。

## 4. 上下文与商品身份

- 每次提问完整包含目标 ASIN，不使用 this item 承接前题。
- 提交前确认 Alexa 界面当前绑定目标 ASIN（若界面提供商品上下文）。
- 回答未复述 ASIN、但界面明确绑定目标 ASIN时，记为界面绑定确认。
- 回答明显指向其他商品或 ASIN 时，该次回答记为商品身份错配。
- 回答与界面都无法确认目标商品时，该次回答记为身份未确认。
- A 或 B 任一个身份错配或未确认时，该字段状态为 ❗ 身份异常；不输出该字段业务事实，不追加身份确认问题。
- 只有身份可信的回答才能进入事实标准化和并集。

## 5. 单次回答标准化

固定字段映射：

    Q1A / Q1B → 用途
    Q2A / Q2B → 场景
    Q3A / Q3B → 人群
    Q4A / Q4B → 特点（独特优势）
    Q5A / Q5B → 痛点（产品限制/用户反馈）

每次回答只提取对应字段。即使 Alexa 在其他问题中说出该字段信息，也不得跨题补入。

标准化顺序：

    原始回答
    → 确认属于目标商品
    → 删除寒暄、购买号召和其他字段信息
    → 删除未归因于目标商品的泛化举例、假设和搜索建议
    → 保留否定、限制、条件、频率和不确定性
    → 拆成独立语义原子事实
    → 单次回答内同义事实去重
    → 形成当前执行的事实集合

原子事实要保留会改变含义的主体、功能、方式、位置、适用对象、条件、数量、单位、范围、否定关系和来源归因。

示例：

    heated kneading lumbar massage

至少拆成：

    功能=massage
    方式=kneading
    加热=heated
    位置=lumbar

## 6. 语义并集算法

设 A 为第一次回答的身份可信原子事实集合，B 为第二次回答的身份可信原子事实集合。最终结果为：

    U = semantic_union(A, B)

### 6.1 双边共同事实

两次使用相同表达或真正等义表达的同一事实，只输出一次，不加来源标记。

示例：

    A：home office
    B：working from home
    U：居家办公

### 6.2 单边事实

- 只在 A 出现：保留并标记 〔A〕。
- 只在 B 出现：保留并标记 〔B〕。
- 不得因为另一遍没有提到而删除。
- 一次更具体、一次更宽泛时，拆成原子事实后保留所有非重复事实；不得把具体单边修饰词降级或删掉。

示例：

    A：heated kneading lumbar massage
    B：lumbar massage
    U：腰部按摩；加热〔A〕；揉捏〔A〕

### 6.3 冲突事实

相同属性下的数值、范围、条件、否定或描述冲突时，两个版本都保留并标明来源，不做裁决或平均。

示例：

    A：支撑在超过 220 磅时下降
    B：支撑在达到 290 磅时下降
    U：支撑在超过 220 磅时下降〔A〕；支撑在达到 290 磅时下降〔B〕

冲突必须同步记录到 conflicting_facts[] 和说明 Sheet 的状态/限制信息中。

### 6.4 无信息与元信息

- “没有详细投诉摘要”“无法查看评论详情”等是 Alexa 的信息可用性说明，不是商品痛点。
- 评分、评论数量、购买建议和“建议查看低星评论”不自动构成当前字段事实。
- Alexa 泛化列举“耐用性、安装、舒适度”等常见问题，若未明确归因于目标 ASIN，不得抓取。
- A/B 都没有商品专属事实时，U 为空并标记 ○ 未抓取到。
- A/B 只有一边有商品专属事实时，保留单边事实。

## 7. 特点与痛点规则

### 7.1 特点

- Alexa 明确说明某功能使商品区别于基础同类产品时，可标记为差异化特点。
- Alexa 只说明功能本身时，只写突出特点，不升级为市场独特优势。
- A/B 提到不同特点时全部进入并集，并按来源标记单边内容。
- 不得据此宣称全市场唯一、最佳或竞品不存在同类功能。

### 7.2 痛点

- 产品页或厂商信息中的限制，只能表述为 Alexa 提到的产品限制。
- Alexa 明确归因于客户投诉或客户反馈的主题，才能表述为用户反馈主题。
- 不得把产品限制改写成真实用户抱怨。
- 泛化的“常见游戏椅问题”或 Alexa 建议用户自行检查的方面，不属于目标商品痛点。
- 频率表述只按 Alexa 原话保留；若 A/B 频率冲突，两个版本分别标记来源。
- 两遍都没有足够信息时写未抓取到，不得写产品没有缺点。

## 8. 字段状态

- ✅ 双次并集：A、B 两遍均执行、身份可信且都有可提取事实；结果为两遍全部事实的并集。
- ⚠️ 单边有内容：A、B 都执行并确认身份，但只有一遍给出可提取事实；保留该单边事实。
- ⚠️ 仅单次执行：一遍因技术原因未完成，另一遍已有身份可信事实；保留已完成内容。
- ○ 未抓取到：两遍都执行并确认身份，但都没有商品专属字段事实；不表示事实不存在。
- ❗ 身份异常：任一回答商品身份错配或未确认；该字段不输出业务事实。
- ⏸ 未执行：没有可用执行结果，包括两遍未执行或剩余队列因技术停止未执行。

状态描述执行与证据覆盖，不表示 Alexa 事实已被外部验证。

## 9. Excel 固定输出结构

主交付为一个 .xlsx，固定包含两个 Sheet。

### 9.1 Sheet：抓取结果

一行一个 ASIN，列顺序固定：

| ASIN | 用途 | 场景 | 人群 | 特点（独特优势） | 痛点（产品限制/用户反馈） |
|---|---|---|---|---|---|

规则：

- 第一列必须是 ASIN。
- 五个维度横向展开，不再为每个 ASIN 输出五行。
- 内容单元格只放并集事实；来源标记使用 〔A〕/〔B〕。
- 无事实时只写：未抓取到、身份异常，未纳入、未执行。
- 不把状态解释、执行说明或原始长回答混入该 Sheet。
- 设置表头筛选、冻结首行和 ASIN 列、自动换行、适度列宽和按内容调整的行高。

### 9.2 Sheet：说明

至少包含：

1. 执行信息：来源、处理模式、站点/语言、执行日期、输入统计、执行统计和停止原因。
2. 并集与来源标记：A∪B、〔A〕、〔B〕、无标记、冲突内容和身份边界。
3. 状态说明：六种固定状态及含义。
4. 来源限制：痛点口径、未抓取到、外部补全禁令和并集风险。
5. 字段状态明细：一行一个 ASIN，列为 ASIN、用途状态、场景状态、人群状态、特点状态、痛点状态。

状态明细使用一致的条件配色，便于筛查异常和未执行字段。

### 9.3 必要限制说明

说明 Sheet 必须包含以下等义内容：

    以上内容仅来自 Alexa for Shopping。每个参数使用同一固定问题在两个独立上下文中各询问一次，最终结果保留任一遍出现的身份可信语义事实并集；未使用 Amazon Listing、评论页面、Q&A、普通网页或其他来源补充。特点不代表已完成市场唯一性验证；痛点同时可能包含 Alexa 表述的产品限制与用户反馈主题，不代表已完成评论原文审计。单边事实提高召回率，但不代表稳定、正确或已被另一遍验证。

### 9.4 文件与审计

- 使用可用的 Spreadsheets Skill 和规定的工作簿工具创建、检查、渲染并导出 Excel。
- 输出文件名建议：Alexa商品洞察并集结果-YYYY-MM-DD.xlsx。
- 除非用户明确要求，不增加第三个 Sheet，不额外交付 Markdown 主表。
- 原始 A/B 问答、身份、技术状态和证据定位保留在本地审计记录中，不塞入业务主表。

## 10. 异常处理

| 情况 | 处理 |
|---|---|
| 一次有内容、一次无商品事实 | 保留有内容的一边；⚠️ 单边有内容 |
| 两次都有不同事实 | 全部保留，单边事实标记来源；✅ 双次并集 |
| 两次同一属性数值冲突 | 两个版本都保留并标记来源；记录冲突 |
| 两次都明确不知道或只给元信息 | ○ 未抓取到 |
| 任一次商品身份错配或未确认 | ❗ 身份异常；该字段不输出业务事实 |
| 一次技术失败、另一遍有事实 | 保留已完成内容；⚠️ 仅单次执行 |
| 两遍都无可用执行结果 | ⏸ 未执行 |
| 登录、验证码、权限、限流或超时 | 记录原因，停止剩余队列，不重试 |
| Alexa 不可访问 | 停止；不得改用网页或其他 AI |

严格限制为两次询问。不得追加第三次询问，也不得重复运行来挑选结果。

## 11. 最终自检

- [ ] 每个合法 ASIN 有 Q1A–Q5B 共 10 个记录，或每个未执行项都有明确原因。
- [ ] 每组 A/B 问题逐字符一致，仅替换同一 ASIN。
- [ ] A/B 在相互独立、无答案污染的上下文中执行。
- [ ] 没有改写、追问、第三次询问或重跑择优。
- [ ] 每次回答只用于对应字段，没有跨题补全。
- [ ] A/B 分别原子化后才计算语义并集。
- [ ] 所有身份可信的双边和单边事实均进入并集。
- [ ] 等义事实已去重；单边事实已标来源；冲突事实两边都保留。
- [ ] 泛化举例、假设、元信息和未归因于目标商品的建议没有进入结果。
- [ ] 产品限制没有被冒充成用户投诉。
- [ ] 技术失败、身份异常、未抓取到和未执行已分开。
- [ ] Excel 只有抓取结果与说明两个 Sheet，主表一行一个 ASIN 且列顺序固定。
- [ ] 已验证工作簿数据、错误扫描与两张 Sheet 的视觉可读性。
- [ ] 未生成用户未要求的 Listing 文案、优化建议、竞品结论或外部验证。
