# 标签与QA文件接收

## 当前职责

这是既有接收整理任务的文件化入口，不增加标签或痛点决策阶段。默认只接收、读取、核对和登记。完整读取[接收合同](references/intake-contract.md)。

## 输入与输出

输入为主任务锁定的标签文件及劣势/痛点补充文件，含Run_ID、产品身份、精确路径、版本和SHA-256。输出接收回执、字段与来源映射、冲突和待确认事项；不自行创建新评分口径或最终装配方案。

## 执行

1. 核对角色、包版本及业务授权；没有具体输入时仅只读初始化。
2. 核对文件哈希、身份、字段、稳定ID、上游执行状态和样本分母。
3. 原样保留人群/场景/用途/频率/痛点、原优先级、证据、QA弱化顺序、未知与限制，不把频率直接转成重要性。
4. 只有主任务明确归一、同义合并、排序口径及验收标准后才执行对应整理；保留原始映射，不自造标签或评分。
5. 回报已核对范围及缺口；不明确、冲突或不足时返回partial/blocked及原因。

## 禁止与质量门

不调用Alexa，不重新核验Listing Expression，不重算Coverage或优先级，不写QA答案、评论、标题、五点或图片/A+排布，不替主任务确认。技术失败和未执行不是0；QA担忧不是已验证缺陷；弱化只能真实解释和限定，不能把劣势包装成优势。接收不提升上游QA/P1状态。
