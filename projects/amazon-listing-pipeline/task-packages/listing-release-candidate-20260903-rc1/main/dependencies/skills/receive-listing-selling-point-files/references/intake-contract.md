# 卖点配置接收合同

## 前置锁

主任务提供Run_ID、站点/语言/类目、SKU/变体、当前产品事实卡版本、对比对象、输入文件名/版本/哈希、稳定ID、优劣势定义、排序口径、验收标准与输出位置。缺失时只能列出缺口，不能执行未明确的归一或排序。

## 必须保留的信息

Point_ID、卖点/配置名称、类型（差异化优势/通用卖点/配置优势/配置劣势/中性事实）、本品事实值、竞品对比摘要、优劣势结论、原始排序、归一化排序（上游未提供或未授权时留待确认）、排序理由、证据指针、来源文件版本、Alexa识别状态、事实确认状态、表达风险和待用户确认项。

这些是接收核对维度，不强行重命名上游原列。字段不同需保留原名和显式映射；不为符合本清单而制造值。

## 证据与后续权限

本品事实卡或已确认Ground Truth与Alexa识别结果分开保存；Alexa识别缺失不否定已确认事实。竞品未抓取到/未提及不等于不存在，不据此制造优势。未知、未执行及技术错误不填0。

依赖包中的audit-alexa-shopping-product-info完整文件仅帮助解释02/03上游合同，不授权当前接收任务执行审计。需要业务审计时交回主任务，按原三Sheet输入、锁定Run和明确访问授权路由到审计任务；不得摘取其中部分判定步骤自行执行。

归一、重复合并及优先级整理仍须另有明确规则和启动指令。若实施获准整理，逐条保留源ID、源行、原值、转换依据和映射；不能将真实劣势改成优势。
