# 质量闸门

所有门槛只在本文件维护。阶段文件不得另造冲突阈值。

## Gate 0｜输入结构

先按 `project-adapter.md` 选择模式。以下三 Sheet 阻断条件仅适用于 `full_pipeline`；`downstream_intake` 必须改为核对封存包的 Run_ID、01–05 数量、固定文件名、逐文件 SHA-256、XLSX 完整性和产品身份。

阻断条件：

- 三张必需 Sheet 或固定列缺失；
- 本品记录数不是 1；
- 必需 Ground Truth 为空；
- ASIN 非法或本品混入竞品；
- 五类对标竞品任一为空；
- 工作簿结构无法可靠读取。

通过后才允许创建正式 Run。

## Gate 1｜运行证据

- Alexa 登录、验证码、权限、网络、浏览器和限流是技术状态，不是无信息。
- 未执行、身份异常和抓取失败不得转成 0 分或“竞品没有”。
- 每个依赖 Skill 的来源边界、问题次数、重试规则和固定输出必须保持不变。

## Gate 2｜商品事实

对每个核心卖点候选，作为公开声明所需的产品事实必须满足：

- Ground Truth 非空且内部不冲突；
- 若 Alexa 审计为 ❗，明确区分“Alexa 未识别”与“Ground Truth 待确认”；
- 数值冲突、单位冲突、包装/本体维度混淆不能作为优势证据；
- Proofability 必须至少为 1；进入核心主张建议为 2。

审计正确抓取率不要求达到 100% 才能继续，因为它衡量 Alexa 识别，不自动否定 Ground Truth。但任何涉及核心主张的事实冲突必须在人工确认时显式展示。

## Gate 3｜样本充分性

默认正式样本最低数为 10，以运行配置 `formal_sample_min` 为准。

- 标签有效竞品数少于门槛：可试算，不得称为正式市场优先级。
- 痛点有效 ASIN 数少于门槛：痛点只能作为个案风险，不能按频率参与核心卖点排序。
- 关键词样本或数据源不完整：保留搜索量/ABA 为空，不得补 0 或捏造。
- 介绍度有效样本不足：保留未验证状态，不得按 Expression=0。

## Gate 4｜关键词可用性

跨项目请求与回执按[关键词交接合同](keyword-handoff-contract.md)核验；附加输入不完整、身份/哈希/事实血缘不闭环或主线程未发本Run READY时，不启动SKU处理。预接收不是授权。合法ABA缺失由SKU合同窄兼容，不因缺失值本身捏造F层或删掉合法候选；结构/证据矛盾仍停止受影响交接。

关键词进入字段分配前必须同时满足：

- 与当前商品和变体真实相关；
- 不依赖商品不具备的功能、材质、颜色、人群或用途；
- 搜索量、ABA、趋势或竞争数据有明确数据源；
- 品类根词与当前商品定位可解释；Office/Gaming 等跨品类定位存在冲突时必须在决策包提示。

以下任一情况发生时，关键词阶段为 `needs_input`：产品输入尚未成功下发给 Amazon 关键词主任务；完整关键词总工作簿尚未正式回传；总工作簿未经 SKU 副线程处理；SKU 副线程尚未交付合格 06；任一段 Run_ID、路径、SHA-256、XLSX 完整性或产品身份不一致。允许先完成人工卖点确认，但不得生成最终 Search Terms 或宣称埋词完成。

## Gate 5｜核心卖点候选

候选必须形成完整链：

`人群 → 场景 → 用途 → 产品结构/参数 → 消费者收益 → 差异或必要性 → 证据`

以下候选不得建议为最终核心主张：

- Direct Fit=0 或 Proofability=0；
- 只因为竞品未提及就声称本品独有；
- 只凭最高搜索量而与确认产品事实不符；
- 只凭单个竞品痛点或 N<正式门槛的 100% 频率；
- 使用最高级、绝对化、医疗、保证或其他不可证明声明。

## Gate 6｜人工确认

确认记录必须锁定 `07_核心卖点决策包.xlsx` 的精确路径和 SHA-256，并覆盖：

1. 人群、场景、用途、频率标签排序；
2. 全部卖点及优势/劣势；
3. 痛点与样本限制；
4. P0 卖点选择（候选 ID 或 `CUSTOM`）；
5. 主图 1–9 初步排布；
6. A+ 1–7 初步排布及动态挤压；
7. ST 去重范围等未决规则；
8. 用户确认时间、确认人、修改说明与仍存在的事实/样本风险。

任何一项仍为待确认、被修改后尚未重排，或校准文件哈希与确认记录不一致，都不得进入埋词、Listing 正文和最终主图/A+装配。

## Gate 6B｜实际文案确认（新版 Run）

07 七项确认后，主线程展示标题、Item Highlights 和全部 Bullet（当前policy至少5条、通常5–6条） 的完整英文，与用户讨论修改后锁定 `copy_checkpoint`。必须满足：

- 用户明确确认实际正文，不以信息排序已确认、沉默或“开始写”代替；
- 文案 JSON Run_ID、产品身份、正文 SHA-256 与来源锁一致；00、人工事实补充、06、07 均可复核；
- 正文或任何已锁定来源发生改变，必须重新确认；不得只刷新哈希冒充已批准；
- 最终 ST 在文案确认后计算，按已确认口径对标题/IH/五点去重；
- 该门只对新建 schema 2.0 默认启用；已封存 schema 1.0 不追溯改写。

## Gate 7｜最终 Listing

必须同时通过：

- 已确认正文与交付标题/IH/五点逐字一致，复制和装配不得自行润色；
- 标题≤75、Item Highlights≤125；v2.2均无颜色，Title无泛套装填充，IH按IH-TITLE-DEDUPE-01不重复Title已表达卖点（含T0）；其他标题、五点格式、ST、图片和 A+ 对应硬规则；
- Bullet条数与当前写法版本及确认记录一致（当前policy至少5条、通常5–6条；五条完整就不补第六条，超过六条须有真实环境/条数确认）；项目固定最低字数、目标区间和上限全部取消，不再设置 255/500 阈值或“长度例外”；
- 实际 Seller Central/站点/类目限制已提供时单独校验；未核验时如实标明，不宣称后台已通过；
- 跨字段事实一致，公开参数、材质、功能、配件、认证和比较均有证据；
- 搜索关键词仅来自当前已验收 06 的 `SKU可用关键词库` Sheet；必要自然语法和已确认产品事实不是新增关键词数据；
- 关键词分配与实际覆盖相符，ST 按确认范围去重并校验 UTF-8 bytes；
- 已采用的标签和卖点按确认优先级覆盖，未采用标签不得悄悄填回；
- 无占位文本、内部备注、ASIN、竞品品牌和禁止内容；
- 新版 10 的 14 Sheet 名称/顺序、四张来源表完整性与三张 T 优先级展示遵循 `knowledge-base/final-workbook-presentation.md`；来源公式、图表、格式和关系不能丢失；
- 优先级展示与已确认 07 逐项可追溯，P0 融入卖点展示但不删除内部审计记录；频率未知不得填 0。

按 `listing-title-highlight-writing-rules.md` 和 `listing-soft-writing-rules.md` 独立检查软性质量。任何事实/硬规则/来源/确认闸门未解决都不能标记 `final_qa=completed`。软性“可优化”可交付但如实保留。取消内部字符限制不等于免除内容质量，也不代表 Amazon 审核通过。
