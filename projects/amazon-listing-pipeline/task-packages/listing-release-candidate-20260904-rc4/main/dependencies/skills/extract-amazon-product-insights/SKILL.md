# Alexa ASIN 五参数双问并集

## 目标

用户只需提供一个或多个 ASIN。对每个合法 ASIN，分别从 Alexa for Shopping 获取：

1. 用途
2. 场景
3. 人群
4. 特点（独特优势）
5. 痛点（产品限制/用户反馈）

每个参数使用一个固定问题并原样提交两遍。Amazon-US使用两个相互独立的干净上下文；Amazon-DE的Rufus没有可依赖的New Chat且刷新后上下文可能保留，按已确认例外在同一持续上下文执行并记录`context_independence=not_available`。A、B 回答分别标准化并拆成原子事实，最终输出身份可信事实的语义并集 A∪B：任一遍出现的商品专属事实都保留。

双问用于扩大覆盖并保留来源差异，不用于过滤单边事实。特点是 Alexa 表述的突出或差异化特点，不代表市场唯一性验证；痛点可以包括 Alexa 明确归因于目标商品的产品限制或用户反馈主题，不代表已核对评论原文。

## 开始前读取

每次执行本 Skill 时，完整读取 [references/alexa-five-questions-and-output-rules.md](references/alexa-five-questions-and-output-rules.md)。该文件规定固定问题、双问隔离、事实标准化、并集算法、状态和 Excel 输出结构。

## 输入合同

- 接受单个或多个 ASIN；允许换行、逗号、空格、表格单元格或文件列输入。
- 去除不可见字符和首尾空格，转为大写，以 ^[A-Z0-9]{10}$ 校验并按首次出现顺序去重。
- `marketplace`为必填且只允许`Amazon-US`或`Amazon-DE`。Amazon-US使用Alexa for Shopping与固定英语问题；Amazon-DE使用amazon.de内Rufus、邮编80539与固定德语等义问题。不得缺省后静默按US执行。
- 部分 ASIN 非法时列出非法值并继续合法 ASIN；没有合法 ASIN 时停止。

## 唯一来源边界

- 只能使用Run站点内可访问的Alexa for Shopping或Rufus界面，或用户明确提供的两组对应购物助手原始问答。输入与站点锁定后，主任务会在登录准备阶段引导用户在本任务Amazon会话手动登录；必须取得本Task/host绑定的`listing:five-dimension-insights:amazon`、`authenticated_web`回执后才可提问，其他任务登录态不能代替。进入非锁定站点须停止并通知用户介入。
- 禁止读取 Amazon Listing、评论页、Q&A、品牌官网、普通搜索结果、第三方页面或其他 AI 摘要补充字段事实。
- 禁止用模型常识、其他 ASIN、用户期待或外部材料补全回答或并集。
- Alexa 引用 Listing、厂商信息或客户反馈时，只能标记为 Alexa 表述，不得冒充已核对原始页面或评论。
- Alexa 的泛化举例、假设性问题和“建议查看耐用性/安装”等搜索建议，若未明确归因于目标 ASIN，不得作为商品事实。
- 页面、网络、登录、验证码、权限、限流或 Alexa 不可访问属于未执行，不是未抓取到。

## 执行规则

1. 规范化并去重 ASIN。
2. 对每个合法 ASIN，固定按 Q1A→Q1B→Q2A→Q2B→Q3A→Q3B→Q4A→Q4B→Q5A→Q5B 执行，共 10 次询问。
3. 同一参数的 A/B 使用完全相同的问题文本，只替换同一个 ASIN；不得改写、补问或澄清。
4. Amazon-US每次询问使用新的、无前题答案污染的上下文，B不能看到A。Amazon-DE不把刷新当作清空上下文，不反复刷新且不因上下文持续阻断；每题必须自含ASIN并记录站点例外。Rufus面板已显示时直接输入，不能再次点击开关将其隐藏。
5. 每次回答只提取当前问题对应字段；不得跨题、跨字段补全。
6. A/B 分别确认商品身份、标准化并拆成原子事实，再计算语义并集；不得直接拼接原始回答。
7. 两遍都支持的等义事实去重后只写一次；仅 A 出现标记 〔A〕，仅 B 出现标记 〔B〕。
8. 数值、范围、条件或描述冲突时，两个版本都保留并分别标记 〔A〕/〔B〕，不得择优或静默合并。
9. 任一回答明显指向错误商品或身份无法确认时，该字段标记为 ❗ 身份异常，不输出该字段业务事实；原始回答只留审计。
10. 一遍技术失败、另一遍有身份可信事实时，保留已完成事实并标记 ⚠️ 仅单次执行；两遍都无可用执行结果时标记 ⏸ 未执行。
11. A/B 都执行并确认身份，但只有一遍给出事实时，保留单边事实并标记 ⚠️ 单边有内容。
12. A/B 都执行并确认身份，但都没有商品专属事实时，标记 ○ 未抓取到；这不表示事实不存在。
13. 不追加第三问，不重复运行来挑选更完整或更有利的结果。遇到登录、验证码、权限、限流、超时或 Alexa 不可访问时记录原因并停止剩余队列，不重试。

## 输出合同

- 主交付固定为一个 .xlsx；除非用户明确要求，不再额外交付 Markdown 主表。
- 生成 Excel 时使用可用的 Spreadsheets Skill 和其规定的工作簿工具，并完成结构、错误与视觉验证。
- 工作簿固定包含两个 Sheet：
  - 抓取结果：第一列 ASIN，后续横向依次为 用途、场景、人群、特点（独特优势）、痛点（产品限制/用户反馈）；每个 ASIN 一行。
  - 说明：执行信息、并集与来源标记、状态说明、来源限制、停止原因，以及逐 ASIN 的五维状态明细。
- 抓取结果 Sheet 的内容单元格只放并集事实或明确占位：未抓取到、身份异常，未纳入、未执行；状态不混入内容正文。
- 说明 Sheet 的状态明细固定使用：✅ 双次并集、⚠️ 单边有内容、⚠️ 仅单次执行、○ 未抓取到、❗ 身份异常、⏸ 未执行。
- Excel 必须设置表头筛选、冻结首行和 ASIN 列、文本自动换行、适度列宽、按内容调整行高；状态明细使用一致的条件配色。
- 原始 A/B 问答与技术状态保留为本地审计记录；除非用户要求，不增加第三个 Sheet，也不把原始长回答塞入业务主表。

## 交付前检查

- 每个合法 ASIN 恰好有 Q1A–Q5B 共 10 个执行记录，或每个未执行项都有明确原因。
- 每组 A/B 问题逐字符一致，仅替换同一 ASIN；Amazon-US上下文相互隔离，Amazon-DE明确记录无法隔离。
- 每次回答只用于对应字段，没有跨题补全。
- A/B 已分别原子化；并集包含全部身份可信的单边与双边事实。
- 等义事实已去重；单边事实有来源标记；冲突事实两边都保留且不裁决。
- 泛化举例、假设性问题和未归因于目标商品的建议未进入结果。
- 技术失败、身份异常、未抓取到和未执行已分开。
- Excel 仅含抓取结果与说明两个 Sheet；抓取结果一行一个 ASIN，列顺序固定。
- 已逐行检查全部 ASIN 的数据完整性、工作簿错误和两张 Sheet 的视觉可读性。
- 未生成用户未要求的 Listing 文案、优化建议、竞品排序或外部验证。
