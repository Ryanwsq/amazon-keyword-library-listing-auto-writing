## 修订沿革与失效方向

| 修订 | 保留的决定及适用范围 | 原方向的状态 |
|---|---|---|
| TITLE-CORE-ROOT-01 | 标题先确认核心词根；从有来源的合格候选按原搜索量排序，再与确认卖点对照；合并不弱化核心品类身份 | “搜索量仅作同级参考”不是现行顺序 |
| IH-TITLE-DEDUPE-01 | IH先排除Title已表达卖点，含T0；补未表达的重要信息，按语义去重，不禁止必要品类词复用或Bullet深入解释 | “标题已覆盖T0仍必须在IH重复”已被替代 |
| BULLET-COVERAGE-COUNT-01 | 至少五条，通常五至六条；按自然合讲后的必要覆盖决定，第六条不凑数；超过六条先确认环境及条数，全部实际文字仍须确认 | “固定五条”“新Run默认六条”均不作为现行条数规则；历史Run保留原合同 |
| FRONT-COPY-DISADVANTAGE-EXCLUDE-01 | Title/IH/Bullet的通用卖点沿确认顺序跳过已确认劣势；真实、有流量或需要背书不构成回填理由；必要安全/适配披露不能省略 | 事实卡有参数不等于该参数应被前台宣传 |
| CATEGORY-CONTENT-ROLE-01 | 区分本体功能、配置证据、真实随附配件；关联配置服务一个购买理由，不把整机部件列表复制成配件条或用于凑数 | 配置背书不是固定末条，也不必独立占条 |
| FRONT-COPY-DIMENSION-EXPRESSION-01 | Title/IH/Bullet均按类目依据、买家理解及必要适配判断数字表达；先解释可感知价值，不一律删数值或推断全市场优势 | 不能靠裸数字或无依据“加宽”替代证明 |
| IH-COMPONENT-GROUP-01 | 同一部件、同一购买理由的相关属性可合讲；保留原卖点ID、顺序和事实 | 不借高优先级主题塞入无关配置 |
| IH-BENEFIT-DEDUPE-01 | IH同一收益下重叠配置按当前SKU确认优先级取舍，不删除内部事实或Bullet的有效机制说明 | 个例材料取舍不是跨SKU永久优劣次序 |
| 文字预算与事实 | Title≤75、IH≤125，均无颜色；Bullet无项目固定字符上下限，实际后台限制独立核验；数字、品牌、售后各按当前事实 | 单次上传反馈不证明全站规则；不补造保证、人数或性能 |
| 双确认与原表保真 | 先确认七类信息决策，再确认整套实际正文；其后生成ST、09实际覆盖及十四Sheet；四张来源表按授权OOXML保真合同复制 | 信息排序确认不代替正文确认；结构测试不代替P1 |

## 内容组织及证据边界

Title/IH可以紧凑短语表达，Bullet仍须自然连贯。每条围绕一个购买理由，组合共同服务该用途的配置，按匹配度选择确认标签；先有内容再补库内关键词。主动埋词去重与必要自然复用区分，具体粒度按当前确认记录，不默认禁止全部共同词根。

完整源词流量不转记为抽出的词根或新组合流量，不累加重叠指标、不虚报跨片段命中。售后期限、在线时段、回复时效是不同事实；不得自动补入保障。关系性用途必须有当前SKU事实支持，不能由配件名推导兼容、安全、保冷时长或水域性能。

主图/A+可以共用优先级、共同用途和标签适配逻辑，但不套用Bullet条数或文字埋词；图位、复现额度和动态挤压仍按已确认合同。原规则中的匿名例子只说明表达差异，不能移入新事实卡或变为市场结论。

## 历史保护与迭代方法

旧正文、输入、06、07、09、10及其状态不因规则升级而改变。局部重写须明确授权、另存草稿并确认；获准替换时先保留原件、登记旧新哈希和受影响依赖，不扩展到其他Run或上游重跑。讨论期的暂停、草案版本及恢复路径属于本地历史，不作为当前执行命令迁入。

后续多案例方法保留在完整知识库：记录反馈、修订、确认及反例，区分通用方法、类目惯例与SKU个例；未经真实验证不创建accepted案例，不把本候选或匿名说明当P1。未确认的流程待办仍未实施。
