# 多案例驱动的核心写法迭代

- 方向ID：ITER-WRITING-004
- 用户确认日期：2026-09-03
- 用户要求：“后续 通过多次验证案例 汇总迭代通用的核心写法”
- 范围：Title、Item Highlight与Bullet Points；作为后续实际验证的复盘方法，不代表已验证其他类目，也不启动后台任务或重跑历史案例。

## 每轮保留什么

记录当前Run/类目/SKU、事实与词库来源及版本、已确认卖点/标签优先级、修改前后正文、用户反馈及修改理由、最终确认状态，以及支持或反对候选规则的案例。待确认稿、被否定稿和确认稿分开，不把“生成成功”当作用户认可。

## 如何归纳

1. 先区分反馈属于通用判断方法、特定类目的表达惯例，还是单个SKU的事实/取舍；暂不能判断时保留为候选，不强行归类。
2. 在后续多个真实案例中对照相同问题，关注不同类目的适用条件及反例。同类目的重复成功不能单独证明跨类目成立，不按机械案例数量自动升级。
3. 可复用结论抽象为“在什么条件下，怎样选择/组织/表达，哪些情况不适用”，不把某句文案、某种配置或某个产品排序当通用模板。
4. 抽象后的规则回查已有案例：应解决原问题，又不推翻其他案例的有效写法；存在冲突就缩小适用范围、记录例外或继续观察。
5. 汇总规则调整及依据，与用户讨论后按确认范围更新对应Skills和知识库，保留版本、案例指针及例外。用户明确要求立即生效的通用纠正不必等待凑够案例；后续案例继续检验其边界。

## 三层结果

- 通用核心写法：跨产品可复用的选词、排序、信息组合、价值表达、去重和确认方法。
- 类目适配：尺寸是否具有直接选购意义、必要适配信息、真实配件展示方式等有条件的规律。
- SKU案例：当前产品的具体词根、参数、T0、优劣势与用户选择；只作为证据，不移植为新SKU事实。

当前写法以[Title/IH知识库](listing-title-highlight-writing-rules.md)和[五点软性知识库](listing-soft-writing-rules.md)为准。本方法不更改现有长度、条数、词源或确认边界，不追溯覆盖交付正文；需要局部重写时按当次授权及正文确认执行。用户认可、字符检查或成功上传不等于已证明转化提升或所有类目适用。
