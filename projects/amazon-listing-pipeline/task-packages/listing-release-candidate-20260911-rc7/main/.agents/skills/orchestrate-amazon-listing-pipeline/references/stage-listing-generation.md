# 阶段：Listing 文案、确认与最终装配

## 版本与前置条件

新建 schema 2.0 Run 执行本流程；已锁定 schema 1.0 Run 保留其原规则版本和七 Sheet 交付，不静默迁移。

开始草稿前必须满足：07 七类信息校准已全部确认且 SHA-256 未变；06 已验收；关键商品事实无未处理阻断冲突；09 落位计划已完成。实际字符统计和覆盖在正文确认后再回填，不以 0 代替未执行。

开始最终装配前还必须满足：`copy_checkpoint=confirmed`，完整标题/IH/全部已确认 Bullet 的精确正文及 00/人工事实补充/06/07 来源锁均有效。只确认卖点或“开始写”不能代替文案确认。

## 执行顺序

1. 完整读取硬规则 Skill 及标题、五点、ST、图片、A+ 五份 reference，再读项目知识库 `listing-title-highlight-writing-rules.md`、`listing-soft-writing-rules.md`、`listing-final-assembly-rules.md`、`final-workbook-presentation.md` 和 `stage-copy-review.md`。
2. 读取已确认 07、09 计划、已验收 06、当前产品事实及人工补充。关键词仅来自 06 的 `SKU可用关键词库` Sheet；可以自然描述确认事实，不得制造新搜索词或指标。
3. 允许参考直接竞品的表达结构、具体场景和叙述节奏，登记来源；不照抄原句，不移植竞品配置、效果、保障和库外关键词，不改变 Alexa 专属上游来源边界。
4. 生成标题/IH/五点完整草稿，做硬规则与软性质量检查，保存带来源锁的版本 JSON。在聊天中展示实际英文、卖点/埋词意图和需要讨论的差异。
5. 主线程与用户逐项修改、确认实际正文，用 `confirm-copy` 锁定。尚未确认则停止在文案门，不生成最终 ST/10。正文或来源改变时 `reopen-copy` 后重审，不能自行更换批准哈希。
6. 依据已确认正文计算最终 ST；依 07 人工选择执行去重范围、UTF-8 字节校验和 09 实际覆盖回填。不得为了埋词偷偷改已确认正文。
7. 从[固定布局数据](final-workbook-schema.json)取Sheet顺序和既有表头，先用`scripts/final_workbook_schema.py --scaffold --phase base`取得10张自建表的结构；保留开放布局表的既有来源信息，不自行删减固定列。在渲染/搬表前执行`--rows-json <按Sheet顺序的行矩阵JSON> --phase base`，再用Spreadsheets Skill生成正文/展示表并查看布局。四张来源表随后按保真合同复制，最终以`--xlsx <10文件> --phase final`复核14Sheet及固定文件名。三张展示表不重新作业务判断。
8. 将 07 已确认 IMG-01–09、A+-01–07 逐位装填；发现冲突时明确重新确认，不静默改优先级、P0 或挤压结果。
9. 在本次装配内检查内容、事实、来源哈希、公式/图表、覆盖、重复标签、可视化和全部Sheet；不另派独立QA。最终渲染及源表审计完成后再封存并回传正式回执，随后登记生成完成及装配内检查完成；文件存在或预览成功不能提前报最终完成。

## 前七 Sheet（后七见展示知识库）

### 1. 确认主张

记录最终中英文主张、人群/场景/用途、事实证明、两次人工确认、来源版本与遗留风险。

### 2. 标题与亮点

`字段｜最终英文内容｜字符数｜核心关键词｜卖点词根｜事实来源｜硬规则状态`

Title≤75，先排06核心大词至中长尾中的带卖点候选原搜索量，再对照确认卖点选词；IH≤125，先排除Title已表达卖点（含T0），再按剩余卖点顺序罗列。两者尽量用足必要信息、无颜色、不强制自然句；正文逐字匹配确认JSON。

### 3. 五点与Search Terms

`序号/字段｜最终英文内容｜字符数或UTF-8字节数｜人群｜场景｜用途｜关键词｜事实来源｜硬规则状态`

v2.2当前至少5条、通常5–6条；先自然合讲关联卖点并核对必要信息覆盖，五条完整就不补第六条，超过六条须先确认环境/条数；T0可分别占条，随后T1/T2用途组合、配置背书、售后。每条一个购买理由，可组合相关配置，写具体动作及买家收益；清单条允许罗列，售后必须有政策。项目固定最低字符、目标区间和上限均取消，不再记录 255/500 的长度例外。仍统计实际长度；当次已知后台限制单列检查，未知状态不得伪装通过。软性质量另列通过/可优化/质量缺口。

### 4. 图片方案

`位置编号｜内容类型｜核心卖点/主题｜卖点优先级｜场景标签｜人群标签｜用途/频率标签｜配置/参数｜关键词｜事实依据｜与其他位置关系｜硬性规则状态｜动态挤压说明`

保留九位置，不为填满而造事实；IMG-01 按确认选择白底或场景。只输出标签式需求预览，不生成图、构图、制作需求、短文案方向。

### 5. A+方案

同上字段，保留七位置及启用/挤压/不采用状态。只输出内容位置预览；不写模块标题、Alt Text 或短文案，不伪造评论。

### 6. 规则校验

`Rule_ID｜字段｜检查项｜实际值｜上限/规则｜状态｜最小修订建议`

硬规则、事实、来源/确认门、软性质量和实际后台核验分开记；取消内部 Bullet 限制不等于 Amazon 已批准。

### 7. 埋词覆盖

从 09 追溯库内每个词/标签的计划与实际落位，记录遗漏、重复和排除理由；不得跨标点/无关句段拼接完整词组命中。

## 后七 Sheet 与验收

依 `final-workbook-presentation.md` 追加 SKU 可用词库、品类产品通用词库、趋势、竞争及三张 T 优先级展示，固定顺序和字段。原表指标未知保持未知，公式和图表不丢失；痛点有效样本不足不能生成市场频率结论或补零。

## 最终机械检查

固定布局检查只检查Schema，不代替以下原有内容/来源/渲染检查。标题/五点/图组/规则表不能合并字段省略列；标签表允许省略确实为空的最后维度，卖点/痛点表允许右加原合同审计列。自建表头应在前10行，不能在正文末尾加一行合规表头掩盖前面的错误表。

- 标签展示先用07已确认身份与09实际采用状态闭合人口：只有采用项进入T分组；其余到“未采用/观察”并保留原因、原优先级、稳定ID和出处，不能按P1/P2/P3直接推断是否采用。
- 痛点先核对上游样本资格及人工排序依据。无合格频率又无人工重要度时写“未排序”，正式频率留空；个案数及分母可另注明，不把原始2/2等比值计算成100%冒充市场频率，也不改04/07原表。
- 09计划与最终实际版另存不同revision路径，不覆盖已确认草案source_locks中的计划。派发中的stage_key继续绑定原计划；最终09由主任务在正式装配回执闭合后登记为实际交付，保留计划引用与旧哈希。
- 先处理自建表换行/行高/列宽，再搬来源表；搬入后不整包重导出。任何后续修改（包括仅行高）都产生新候选和新哈希，重做受影响的检查；不得一边报告旧哈希已最终、一边悄悄覆盖文件。最终09/10、渲染/保真检查及正式回执一次同版本回传。主任务只在收到完整回执后镜像并核对字节哈希。

- Title≤75，IH≤125，其余格式和重复规则按硬规则。
- Bullet条数匹配当前写法合同及确认快照（当前policy至少5条、通常5–6条，超过六条须有环境/条数确认）；无项目固定字符限制，检查独立购买理由、用途组合、事实与自然可读性。
- 已确认正文逐字一致；若需要修改先重新确认。
- ST 小写、单空格、无标点、按已确认范围去重且符合适用 UTF-8 字节上限。
- 09 真实覆盖/计数与 10 一致；四张来源 Sheet 和三张展示 Sheet 来源完整。
- 已采用标签按人工层级落位；主图/A+重复限制与动态挤压正确，无库外搜索词。
- 全部产品事实一致，未知参数不补造，样本不足/未执行/技术失败原样保留。
- 不声称通过 Amazon 审核，不擅自发布、不回写上游、不改写历史已交付 Run。
