# 标签与QA接收合同

## 前置锁

主任务锁定Run_ID、站点/语言/类目、SKU/变体、输入文件名/版本/哈希、稳定ID、标签口径、优先级口径、QA弱化定义、验收标准和输出位置。接口不明时不猜测。

## 必须保留的信息

Tag_ID/Pain_ID、维度、人群/场景/用途/频率/痛点标签、原始优先级、归一化优先级（没有上游值或归一授权时待确认）、SKU匹配状态、证据指针、来源版本、冲突/缺失、QA弱化顺序、可表达/需确认/禁止推断状态。字段不同仅建立明确对应关系，不强改上游Schema。

保留Review使用问题与Customer Q&A购买担忧的区别；保留有效频率及分母、样本限制和执行状态。不得把出现多自动解释为更重要；没有合格频率不造百分比，未知不填0。

## 原规范依赖与后续权限

依赖包内prioritize-amazon-insight-tags和alexa-painpoint-frequency的完整Skill、合同及必要资产用于解释上游输出，不授权当前任务执行采集/评分。若主任务需要重新执行标签业务，须另行匹配完整固定输入合同，并路由到对应负责任务，不摘取局部评分步骤。

归一、同义合并及排序整理需主任务另锁规则；每条变更保持源标签、稳定ID、原值、依据和所有映射。真实劣势只能说明、限定或避险，不能改为虚假优势。最终用户交互与位置确认由主任务负责。
