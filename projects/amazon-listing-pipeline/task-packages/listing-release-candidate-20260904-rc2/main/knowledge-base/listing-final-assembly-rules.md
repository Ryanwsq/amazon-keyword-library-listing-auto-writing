# Listing 最终装配填充规则

## 1. 文档定位

- 知识库ID：`listing-final-assembly-rules`
- 当前版本：`v0.5-writing-v2.2`
- 状态：`ACTIVE_V2_AFTER_VALIDATION_02_DELIVERY`
- 生效日期：`2026-09-03`
- 适用阶段：信息校准完成后，最终Listing文字装配、主图/A+内容位置预览以及未来Q&A/评论规划。

本文件定义各位置“填什么、按什么优先级填、由什么输入提供”。它不替代具体写作Skill，不生成图片或设计稿，也不替代Amazon硬性规则。规则冲突时，当前站点/类目规则及[Listing硬性规则知识库](listing-hard-rules/README.md)优先；用户于2026-09-03取消项目五点固定字符限制，并以v2.2讨论修订Title/IH短语表达、跨字段卖点去重及按覆盖选5–6条的动态描述（至少5条）；实际后台限制仍独立核对。

当前主图/A+动态排布、ST去重范围及对比图口径属于每个 Run 的人工校准对象；未完成人工确认前不得开始最终 Listing 撰写或把排布标记为最终锁定。

## 2. 装配前置门

只有以下输入已接收、版本锁定并完成人机信息校准后，才允许进入最终装配：

1. SKU可用关键词库。
2. 产品事实卡及当前子ASIN/变体事实。
3. 场景、人群、用途、使用频率等标签及优先级。
4. 本品卖点、配置、相较竞品的优势与劣势排序。
5. 品类痛点、竞品痛点及可由本品事实支持的解决关系。
6. 用户在人机交互中确认的P0优先卖点。
7. 标题、Item Highlights、五点描述、Search Terms、图片和A+硬性规则。
8. [标题与五点软性写作规则](listing-soft-writing-rules.md)及适用的口语化表达或语言协调 Skill 输出。

未确认事实、技术失败、未执行、未抓取到或样本不足的内容不能被自动提升为产品事实、市场结论或消费者频率。缺少合格内容时允许空缺或回到信息校准，不得为填满位置而造词、造参数或造卖点。

### 2.1 写作前信息校准顺序

最终写作前必须先产出并由用户逐项确认：

1. 人群、场景、用途、频率标签排序；
2. 全部卖点及优势/劣势；
3. 痛点与样本限制；
4. P0 卖点选择；
5. 主图 1–9 初步排布；
6. A+ 1–7 初步排布及动态挤压；
7. ST 去重范围等未决规则。

其中第 5、6 项是让用户看清“每个位置准备讲什么”的写作前预览，不是最终图片/A+方案。若用户修改 P0、标签或卖点排序，必须先重排受影响的位置并再次确认。七项全部锁定后，才生成Title、Item Highlights和五点的可讨论草案；主线程取得整套正文明确确认后，才生成最终ST、回填09并装配10。

### 2.2 正文交互确认

按总控stage-copy-review.md执行第二道人机确认；信息决策确认不代表正文确认。任何正文、07、06或事实源变化都应保留旧版并重新确认相应内容。新合同不追溯改变已封存Run。

## 3. 全局优先级

装填时按以下顺序解决冲突：

1. Amazon硬性规则与当前站点/类目后台限制。
2. 当前SKU和子ASIN已确认产品事实。
3. 用户在人机交互中锁定的P0优先卖点。
4. 本品相较竞品的优势卖点与可验证配置参数排序。
5. 场景、人群、用途、使用频率等标签优先级。
6. 品类通用卖点的重要程度排序。
7. SKU可用关键词的搜索价值与未覆盖情况。
8. 标题与五点软性写作规则。
9. 口语化表达和语言协调。

口语化表达只能改变“怎么说”，不能改变“事实是什么、优先级是多少”。同一卖点重复须有信息任务；IH按最新IH-TITLE-DEDUPE-01排除Title已表达卖点（含T0），只补未表达的重要信息。此全局顺序不是标题候选排序算法：Title必须先排原搜索量，再与卖点优先级对照选词，详见标题知识库。

### 3.1 主图与A+标签复现规则

来源：用户于2026-09-03确认的排版优化要求。这是项目排版软性规则，不是Amazon平台硬性规则。

- 主图与A+合并检查主动突出的**人群、场景、用途、频率等标签**，不分别计算两个板块的次数。当前按合计口径执行；如用户另行指定范围，以当前Run确认记录为准。
- 只有用户确认的最高优先级标签可以安排两次以加深印象；允许重复不等于必须重复，也不意味着所有最高优先级标签都要出现两次。
- 其他标签默认优先只出现一次。确需重复时，记录必要性和具体位置，交由用户确认，不把“最好一次”误写成不可调整的硬禁令。
- 按语义归一后的标签计数，同义词、近义改写和同一诉求的人群/用途换名不能绕过复现检查。同一张图内重复提及同一标签只算一个位置；轮播中的不同面板按独立位置检查。
- 上游复合标签如“家庭/团体”需要细分为家庭、朋友时，必须记录拆分依据与原标签映射；真实不同人群可分别安排，但不能仅换名称后重复相同画面诉求。
- 排布先满足已确认的P0和固定槽位，再按标签优先级分配尚未覆盖的标签；已用完复现次数的位置可只讲产品配置，不强塞人群或场景，也不为填槽新增无依据标签。
- 同一产品尺寸、配置或P0卖点在不同位置承担尺寸核对、使用收益、结构细节等不同任务，不直接套用人群/场景标签次数；仍须避免同内容原样重复。产品使用不可避免的普通背景不单独算强化标签，但不得借“背景”名义反复突出同一场景。
- 预览必须能追溯每个标签的实际位置与轮播面板；修改首图形式、标签顺序或P0后，重新检查复现分配，再交用户确认。

本轮桨板的局部决定：`BOARD-EXAMPLE` 的家庭标签仅安排在`IMG-04`承重/大板面图与`A+-04`场景轮播的家庭面板。此处是该Run的覆盖限制，不自动套用到其他SKU。

## 4. 文字Listing装配规则

Title、Item Highlights和Bullet在内容选择前统一执行[软性写作规则](listing-soft-writing-rules.md)的FRONT-COPY-DISADVANTAGE-EXCLUDE-01：保留已确认最强T0，其余通用卖点依确认的重要程度顺序核对，遇到本品已确认劣势就跳过，后续合格项依原顺序补位。不因真实、有流量或配置背书需要而补回劣势。事实、源对比和内部决策表仍完整保留；必要披露冲突另行解决，不暗示超出事实的能力。

### 4.1 标题与Item Highlights

- 由对应写作Skill基于锁定输入产草案，经预检后与用户讨论确认；允许参考直接竞品写法，但不移植事实、词源或原句。
- 需要承担搜索作用的关键词只能来自`SKU可用关键词库`。
- 标题先按[标题知识库](listing-title-highlight-writing-rules.md)的TITLE-CORE-ROOT-01确认核心大词词根，只有包含该词根的合格候选才参与原搜索量排序，再对照确认卖点选词；合并不能把已确认核心词根降为泛类目词，有空间补未表达T0，不用set/combo类填充。
- IH按[标题知识库](listing-title-highlight-writing-rules.md)先排除标题已表达卖点，再补未表达T0、3–4项高优先级内容及必要使用/适配信息，基本不看搜索量；标题已覆盖T0不在IH重复。两字段不强制自然句、均无颜色，尽量用足必要信息。
- 标题最多75字符，Item Highlights最多125字符；必须使用确定性计数。
- Title/IH按标题知识库FRONT-COPY-DIMENSION-EXPRESSION-01判断尺寸用数值还是可感知的空间表达；IH再按IH-COMPONENT-GROUP-01合讲相关部件属性、按IH-BENEFIT-DEDUPE-01取舍同一收益下的重叠配置，不改事实或原优先级。
- 内容组织、自然埋词与软性质量以[标题与五点软性写作规则](listing-soft-writing-rules.md)为准。
- 具体边界以[亚马逊标题硬性规则](listing-hard-rules/亚马逊标题硬性规则.md)为准。

### 4.2 五点描述

- 由对应写作Skill基于已确认的卖点、事实、标签、痛点和语言素材直接产出，再经过硬性规则校验。
- v2.2当前至少5条、通常5–6条：T0（可多条，后续顺延）→T1用途组合→T2用途组合→配置/配件背书→真实售后；这是五类内容块，不是机械的一块一条。先自然合讲并核对必要信息，五条完整就停在五条，第六条须有新增必要信息；不得凑数或为压缩而遗漏。超过六条先确认环境/条数，所有实际正文仍需确认。
- 每条一个购买理由，相关卖点可合讲；同一配置再出现须有新用途或信息。按软性知识库CATEGORY-CONTENT-ROLE-01区分本体功能、配置证据和真实随附配件：电竞椅部件不写成桨板式配件清单，配置背书/配件条不固定占末条，也不用于凑数。
- 每条至少包含一个可核验产品证据或工作机制，并形成`产品事实 → 使用变化 → 买家收益`的自然语义链；移动端前半句先给收益和关键信息。
- 尺寸同样执行FRONT-COPY-DIMENSION-EXPRESSION-01：先让买家理解空间和动作，数值仅在说明优势、功能或适配时作背书；证据不等于每条必须有数字，不用尺寸列表替代购买理由。必要限制和原始参数仍保留，主图/A+本次不自动改动。
- 痛点口语表达用于帮助理解用户会怎样描述问题、购买前会怎样提问；最终五点必须以本品已确认事实回答，不得把Alexa归纳表达写成消费者原话或评论证据。
- 需要承担搜索作用的埋词只能来自`SKU可用关键词库`；先剔除Title/IH已分配主动目标，再按余词搜索量与主题适合度补词；不禁必要品类词自然复用，去重粒度单独确认。
- 五点取消项目固定字符目标及上/下限，不再设置长度例外；仍报告计数，以完整证据、自然场景和可读性为准，不凑字数。
- 真实后台有强制限制时登记来源并调整，经用户重新确认后提交；后台限制未知不得写成已通过。
- 使用简短标题头加冒号，结尾不使用结束标点。
- 内容结构、场景/人群/用途写法、自然埋词与软性质量以[标题与五点软性写作规则](listing-soft-writing-rules.md)为准。
- 具体边界以[亚马逊五点描述硬性规则](listing-hard-rules/亚马逊五点描述硬性规则.md)为准。

### 4.3 Search Terms（ST）

- 候选词只来自`SKU可用关键词库`。
- 以07人工锁定的去重范围为准，逐一核对标题、Item Highlights、五点及ST内部；未明确锁定范围不得生成最终ST，不能因简写“标题和五点”而漏掉IH；不得为补足字节加入库外关键词。
- 对候选词执行相关性、品牌/ASIN、主观宣传词、临时促销词和格式禁用检查。
- 最终文本使用小写字母和单个普通空格，不使用标点、首尾空格或连续空格。
- 按当前后台限制进行UTF-8字节校验；默认上限和更严格模板上限以硬性规则为准。
- 具体边界以[亚马逊ST硬性规则](listing-hard-rules/亚马逊ST硬性规则.md)为准。

## 5. 主图及副图内容位置预览

### 5.1 范围

- 最多9张Listing商品图片。
- 本项目只输出每个位置的内容标签、核心卖点、场景、人群、用途、参数和事实依据，不输出真实图片、设计稿、构图、配色或制作需求。
- 第1张仍是MAIN首图，但可以选择白底首图或场景首图。白底方案遵守纯白背景和商品占比要求；场景方案使用已确认的高优先级场景，并保持商品主体清晰、事实一致且不误导随售内容。
- 所有图片仍须满足[亚马逊图片硬性规则](listing-hard-rules/亚马逊图片硬性规则.md)。

### 5.2 固定槽位与填充规则

| 位置 | 固定内容类型 | 填充规则 |
|---|---|---|
| `IMG-01` | 白底首图/场景首图 | 两种方案二选一。白底方案只展示当前子ASIN实际销售商品及随售内容；场景方案选择高优先级场景，并确保商品是清晰核心主体、人物/道具不造成随售误解。两种方案均不放促销、虚假卖点或无依据参数。 |
| `IMG-02` | 场景图 | 在用户指定落位与全套标签复现次数约束下，使用尚可分配的最高优先场景；若`IMG-01`已为场景首图，则使用下一高优先级或互补场景。结合相匹配且尚有复现额度的人群、用途或频率，不强制重复已留给其他槽位的标签。 |
| `IMG-03` | 尺寸/适配图 | 展示已确认产品尺寸、可调范围和适配信息；不得把包装尺寸写成产品尺寸。 |
| `IMG-04` | P0优先卖点图 | 使用人机交互确认的最高优先卖点；与最匹配的场景、人群或用途标签结合。 |
| `IMG-05`–`IMG-09` | 通用卖点图 | 按本品相较竞品的优势卖点/参数排序，再用场景、人群、用途等标签优先级补充表达；每张只承担一个主卖点。 |

### 5.3 IMG-05至IMG-09排序

按以下顺序选择内容：

1. 本品相较竞品具有明确、可验证参数优势的卖点。
2. 对购买决策影响更大的品类通用卖点。
3. 与高优先级场景、人群或用途能够形成明确组合的卖点。
4. 尚未在IMG-02至IMG-04充分表达的卖点。
5. 有充分事实依据且适合图片化理解的配置或细节。

若不足5个合格卖点，不得拆分同一事实或制造弱卖点填满9张；可以减少实际使用图片数量。若存在超过5个合格卖点，低优先级内容转入A+、五点或Q&A候选池。

## 6. Premium A+内容位置预览

### 6.1 范围

- 最多7个Premium A+模块。
- 本项目只决定模块内容主题和标签分配，忽略具体视觉设计、模块尺寸、构图和制作稿。
- 实际模块名称、图片数量和字段限制以Seller Central后台为准。
- 所有模块仍须满足[亚马逊A+硬性规则](listing-hard-rules/亚马逊A+硬性规则.md)。

### 6.2 基础模块框架

| 位置 | 内容类型 | 填充规则 |
|---|---|---|
| `A+-01` | 场景图/场景总览 | 在用户指定落位与主图/A+合计复现约束下，选择最高优先的可用场景或互补场景；可强化经确认的最高优先标签，但不机械重复主图的人群/场景组合。 |
| `A+-02` | P0优先卖点 | 使用人机交互确认的最高优先卖点，结合与其最匹配的场景、人群、用途或使用频率标签。 |
| `A+-03` | 通用卖点轮播 | 承接`IMG-05`至`IMG-09`的通用卖点池；按优势卖点和参数优先级排序，不逐句复制主图或五点。 |
| `A+-04` | 使用场景轮播 | 按场景、人群、用途和使用频率标签优先级排列；每个面板只表达一个清晰组合。 |
| `A+-05` | 产品配置背书 | 优先展示相较竞品更强且已确认的基础配置，例如承重、五星脚、气杆等级等；认证、等级和测试必须有适用证据。 |
| `A+-06` | 弹性/挤压槽 | 默认承接尚未覆盖的最高优先卖点或场景。若存在第2个P0卖点，则本槽优先改为第2个P0模块，并压缩一个最低优先级的非强制补充内容。 |
| `A+-07` | 产品对比 | 只定义对比内容和字段，不处理视觉设计；使用一致条件、单位和定义。Premium A+同品牌对比表只能比较同品牌真实商品，不得展示竞品品牌、ASIN、图片或贬低性内容。 |

### 6.3 动态挤压规则

- A+总模块数不得超过7。
- 第1个P0固定进入`A+-02`。
- 第2个P0优先占用`A+-06`。
- 若P0或必须展示的配置增加，优先压缩最低优先级、已在其他位置充分覆盖的通用卖点或场景补充内容。
- `A+-01`场景总览、`A+-02`首要P0和必要事实背书不得仅为填入更多普通卖点而降级。
- 任何挤压结果都应在人机信息校准预览中显示，用户确认后才锁定最终位置。

## 7. Q&A及评论规划板块

### 7.1 当前状态

状态为`RESERVED_NOT_ACTIVE`。本阶段不执行Q&A或评论内容生产，但在知识库和最终装配结构中保留入口。

### 7.2 未来内容来源

1. **P0卖点补充**：对标题、五点、主图或A+无法完整解释的最高优先卖点进行补充。
2. **不如竞品的配置**：针对本品明确弱于竞品的配置，使用真实、克制的说明或适用边界；不得虚构优势或贬低竞品。
3. **品类通病解决**：当本品事实确实能解决品类通用痛点时，说明解决机制。例如只有事实确认存在皮与网结合结构时，才可以讨论其对皮质闷热问题的改善逻辑。
4. **Rufus未抓取到的本品事实**：将已由产品事实卡确认、但Rufus未抓取到的事实纳入未来Q&A补充池；“未抓取到”不等于产品不具备。

### 7.3 未来边界

- 问题语言可以参考Alexa痛点口语表达，但不得称为消费者原话或评论高频问法。
- 答案必须来自已确认产品事实、说明书、规格或其他合格证据。
- 未执行、技术失败或未抓取到的内容不得填成“无”“不具备”或零频次。
- 本板块不能用于绕过标题、五点、图片或A+的真实性与合规限制。

## 9. 最终校验

完成装配前必须确认：

- 标题、Item Highlights、五点和ST均来自对应Skill及锁定输入。
- 标题、Item Highlights 与五点已按软性写作知识库完成独立质量检查；软性问题不冒充硬性违规。
- 五点无项目固定字符限额，计数可见；实际后台限制单独核验。Title、Highlights、五点逐字等于用户确认快照。
- 需要承担搜索作用的词只来自SKU可用关键词库。
- ST按07人工确认范围核对标题、Item Highlights、五点及ST内部，只补充尚未覆盖的合格词，并完成UTF-8字节校验；任何范围例外须保留确认依据。
- 主图第1张已明确选择合规白底首图或场景首图方案；场景覆盖和尺寸图均已安排。
- P0、通用卖点、场景、人群和用途按确认后的优先级填入。
- 主图最多9张，Premium A+最多7个模块。
- 每个位置只有一个主要信息任务，不用重复内容填满槽位。
- 主图与A+已合并核对标签落位：最高优先标签至多安排两次，其他标签默认一次；例外有用户确认，轮播面板与语义同义表达未漏计。
- 所有产品事实、参数、认证、等级、比较和解决痛点关系均有证据。
- Q&A及评论板块保持未启用，除非后续单独确认执行规则和输出接口。
