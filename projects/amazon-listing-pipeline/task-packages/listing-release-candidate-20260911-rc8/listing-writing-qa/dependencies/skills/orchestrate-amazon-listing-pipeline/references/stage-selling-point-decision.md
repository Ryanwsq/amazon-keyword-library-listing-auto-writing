# 阶段：信息校准与初步排布决策包

## 目的

将彼此独立的四类证据合并成完整的写作前信息校准包，并从中形成最多三个 P0 候选：

1. 商品事实、参数优势和原始卖点排序；
2. 人群、场景、用途、频率及市场内容优先级；
3. 痛点重要性与证据状态；
4. 关键词需求、搜索量和产品可用性。

不得把任一上游表的第一名机械复制为最终卖点。此阶段先完成标签、卖点、痛点、P0、初步位置和未决规则的决策预览；不会撰写最终标题、Item Highlights、五点或 ST。

## 候选构建

每个候选必须包含：

- `Candidate_ID`：`SP-01` 至 `SP-03`；
- 中文核心主张；
- 英文表达方向，不是最终标题；
- 目标人群；
- 使用场景；
- 用途；
- 频率，可空；
- 产品结构/参数证据；
- 解决的标准化痛点，可空；
- 竞品差异或市场必要性；
- 对应关键词簇；
- 商品事实状态；
- 标签样本状态；
- 痛点样本状态；
- 关键词数据状态；
- 主要冲突/风险；
- 推荐层级和可复核理由。

## 决策顺序

不把不同来源指标简单相加成一个不可解释的总分。使用以下闸门和排序键：

1. 淘汰 Direct Fit=0 或 Proofability=0 的链条。
2. 商品事实可确认且 Proofability=2 的候选优先。
3. 标签正式数据优先于试算；同状态下 P1 优先于 P2，P2 优先于 P3。
4. Differentiation=2 优先于 1；不得因竞品未提及而升为 2。
5. 达到正式样本门槛的痛点证据可提升“问题重要性”；不足门槛不参与排序。
6. 产品匹配通过后，核心主张匹配度和购买意图优先于纯搜索量；再按搜索量层级、ABA 和竞争信号排序关键词支持。
7. 仍相同时，沿用本品用户原始卖点顺序，保证确定性。

## 决策包工作簿

使用 Spreadsheets Skill 生成 `07_核心卖点决策包.xlsx`。

### Sheet 1｜标签优先级确认

一行一个标签：

`标签类型｜标准化标签｜原始表达｜原始优先级｜建议优先级｜样本/覆盖状态｜Listing表达方向｜证据来源｜限制说明｜人工状态｜人工调整后优先级`

标签类型至少覆盖人群、场景、用途、使用频率；缺失类型保留空表和缺失原因，不得补造。

### Sheet 2｜卖点优劣势确认

一行一个卖点或配置：

`卖点ID｜卖点/配置｜类型｜原始排序｜建议排序｜优势/劣势/中性｜竞品比较依据｜产品事实状态｜可证明性｜消费者收益｜适合位置｜限制说明｜人工状态｜人工调整后排序`

必须展示全部合格卖点和明确劣势，不得只展示 Top 3。配置参数的重要性与卖点重要性分别确认并保留稳定 ID/来源，不能把卖点名换成参数名冒充独立排序。类型至少区分 `P0候选`、`优势卖点`、`通用卖点`、`劣势/风险`。

### Sheet 3｜痛点与样本限制

一行一个痛点或数据限制：

`Painpoint_ID｜标准化痛点｜品类/竞品范围｜有效ASIN数｜频率/证据状态｜本品事实是否可回应｜可回应卖点ID｜弱化或Q&A方向｜技术失败/未执行说明｜人工状态`

样本不足、技术失败、未执行和 Alexa/Rufus 未抓取到必须分别表达；不得把它们改写为零痛点或产品不具备。

### Sheet 4｜P0卖点选择

一行一个候选，包含上述“候选构建”字段。推荐层级只允许：

- `推荐确认`
- `可选方向`
- `保留观察`
- `不可确认`

另加：`人工选择状态｜人工修改后的中文主张｜人工修改后的英文方向`。未确认前均保持待确认。

### Sheet 5｜主图初步排布

固定保留 `IMG-01`–`IMG-09` 九行，即使合格内容不足也不造内容填满：

`位置编号｜内容类型｜核心卖点/主题｜卖点ID与优先级｜场景标签与优先级｜人群标签与优先级｜用途/频率标签与优先级｜配置/参数｜事实依据｜与其他位置关系｜空位/限制说明｜人工状态｜人工调整`

这里只决定“该位置讲什么”，不是最终图片方案、文案、构图或制作需求。

### Sheet 6｜A+初步排布

固定保留 `A+-01`–`A+-07` 七行：

`位置编号｜内容类型｜核心卖点/主题｜卖点ID与优先级｜场景标签与优先级｜人群标签与优先级｜用途/频率标签与优先级｜配置/参数｜事实依据｜与主图/五点关系｜动态挤压说明｜空位/限制说明｜人工状态｜人工调整`

多个 P0 产生的动态挤压必须在本 Sheet 展示；P0、标签或卖点排序被修改后，重新计算受影响行。

### Sheet 7｜未决规则

一行一个必须由用户锁定的 Run 级规则：

`Rule_ID｜规则主题｜可选口径｜建议口径｜影响字段/位置｜未确认风险｜人工选择｜人工说明｜确认状态`

至少包含 ST 去重范围；如多个 P0、A+ 对比口径、IMG-01 白底/场景选择仍未锁定，也必须列入。

### Sheet 8｜证据与冲突

一行一条证据：

`对象类型｜对象ID｜证据支线｜来源文件｜Sheet/字段｜证据事实｜证据状态｜是否支持｜限制说明`

同一 Sheet 追加质量检查行：

`对象类型=QUALITY_GATE｜Gate_ID｜检查项｜实际值｜门槛/期望｜状态｜影响对象｜建议人工动作`

### Sheet 9｜人工确认

字段：

`确认范围｜确认状态｜确认文件SHA-256｜P0候选ID/CUSTOM｜最终中文核心主张｜最终英文表达方向｜用户修改说明｜确认人｜确认时间｜遗留风险`

确认范围固定列出上述七类对象。确认前写 `待确认`，其余为空。只有七类全部确认且受影响布局已重排，才允许填写总确认记录。

## 人工交互

在聊天中按以下顺序展示：

1. 人群、场景、用途、频率标签排序；
2. 全部卖点及优势/劣势；
3. 痛点与样本限制；
4. 最多三个 P0 候选及其最强支持证据、最大风险和样本状态；
5. 主图 1–9 初步排布；
6. A+ 1–7 初步排布与动态挤压；
7. ST 去重范围等未决规则。

允许用户逐项确认、修改排序/标签/槽位/规则口径、选择或自定义 P0，也可以否决并要求重组。任何修改影响下游初步排布时，更新工作簿并重新展示受影响部分。未收到七类对象全部明确确认前，设置 `human_checkpoint=needs_input` 并结束当前运行回合。

## 新版最终展示与后续确认

07 仍保留上述九 Sheet 作为信息校准与追溯合同。新版最终交付的 `卖点与配置优先级展示` 将 P0 选择融合进卖点排序：最强 T0 在前，随后为已确认通用卖点，第三列独立展示配置参数排序；不删除 07 的 `P0卖点选择` 审计表。标签、卖点、参数、痛点的 T0/T1 映射只按人工确认结果投影，并列保持并列，未知/不采用保留独立状态。

信息校准全部确认仅解锁 09 计划和标题/IH/五点草稿；随后必须按 `stage-copy-review.md` 与用户讨论实际正文并通过第二道确认门，才生成最终 ST、最终 09/10。
