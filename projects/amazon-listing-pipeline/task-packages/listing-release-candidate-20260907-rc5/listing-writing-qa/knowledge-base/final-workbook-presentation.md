## 2. 原表装配保真

用户已授权四张来源表用OOXML底层文件复制方式搬入，并要求固化为Skill。正文/三张展示表仍由表格工具装配；原表不重算，具体执行、脚本、停止条件与验收见[原表保真装配](../dependencies/skills/orchestrate-amazon-listing-pipeline/references/preserved-sheet-transfer.md)。装配后只读检查，不再整包导出导致原缓存/图表被改写。

- 锁定来源Run/产品身份/路径/哈希/Sheet及数据周期；旧类目词库复用许可只涵盖词数据，不涵盖旧SKU事实。
- SKU表保留五字段、行序、原文、翻译、指标类型及空值。其他三个保留源值、公式/缓存、图表及系列、单位、排序、空值和可读样式，不重算业务判断。
- 跨工作簿装配时必须检查公式、图表、SST、样式与关系引用闭包。重映射内部ID允许，但不能仅比较文本或截图便宣称“原表无损”。
- 如果原公式依赖未交付的Sheet，先解决依赖并登记。不得静默折成静态值、产生外链/断链，或为修公式混入其他Run；不能保真时暂停该表装配并说明。
- 记录逐Sheet源/目标的值和公式对应、图表系列及依赖验证，不把下游装配检查称为已取消的上游独立QA。

## 3. 标签优先级展示

第一行表头：`优先级｜人群｜场景｜用途｜使用频率｜其他已确认标签`。确无其他标签时可省末列。

首列自T0、T1、T2向下；各列按该维度已确认的顺序排列，首行是各自最高项。同一行不表示人群/场景/用途之间已建立配对关系；图中真正的组合仍以已确认位置映射为准。保留同级并列：同一格换行列举，不把并列项擅自排成不同重要程度。

只展示已采用标签。未采用、待确认或仅观察标签放该Sheet表后“未采用/观察”区并写原因，不占用T0资源；不存在的维度留空及来源缺口，不能填0或发明标签。T0/T1是展示层的序位/分组，不重新计算Coverage或覆盖上游P1/P2/P3；保留原始优先级、稳定标签ID和源单元格映射。

## 4. 卖点与配置优先级展示

前三列表头固定：`优先级｜卖点优先级（含最强核心卖点）｜配置参数优先级`。必要时右侧加事实/优劣势/证据边界等审计列，但不改变这三列顺序。

- 第二列T0首先显示人工确认的最强卖点；其后按确认顺序列其他已选核心卖点，再列通用卖点的重要程度。保留P0身份及第一/第二核心卖点标记，不把展示层T1误解为取消其原P0身份。
- 第三列独立排列用户确认的配置/参数重要度，包含具体参数、单位及作用对象；同一行的卖点和参数不默认对应。
- 明确优势、劣势、中性和信息未提及差异，不能把后者变成“竞品没有”。弱项与未知保留在表后风险区或右侧边界列，不抹去原判断。
- P0选择已融合本Sheet，不再新增一个“P0卖点选择”交付展示Sheet。原07内部的候选和确认轨迹仍保留，不删除七类确认对象。
- 配置排序如未确认，回07补确认，不由表格装配者另算重要度或为填满T序位造结论。

## 5. 痛点频率与重要级展示

表头：`优先级｜痛点/购买担忧｜有效频率与分母｜重要性及依据｜本品可回应事实｜样本限制/执行状态`，按需要增加稳定ID/来源列。

- 先执行样本和证据闸门，再按已确认的重要度列T0/T1等。频率与重要性分别展示，不把出现多自动等同最重要。
- 样本不足时只能展示试算/个案风险；如果用户明确人工排序，标明“人工重要度，非市场频率排序”。没有合格频率也没有人工重要度时，首列写“未排序”，频率留空并说明原因，不制造T0排名。
- 技术失败、未执行、未识别、产品不具备分别记录。有效分母为0时痛点数仍可能未知，不填0%或“无痛点”。
- 样本限制和未取得内容在Sheet顶部摘要或表后限制区可见，不混入真实痛点T0列表。

## 6. 正文行数兼容

v2.2保持“五点与Search Terms”Sheet名，但按确认bullet_points数组逐条装配Bullet 1–N，当前policy至少5条、通常5–6条，以自然合讲后的必要信息覆盖决定。五条完整不补第六条；不得只复制已确认六条的前五条、覆盖ST行或将第五逻辑块当第五条；ST放全部Bullet之后。超过六条附环境/条数确认依据。旧Run不改变行数或原文。

采用Excel原生表格、冻结首列/表头、换行、适度列宽；T0为最高视觉强调，后续层级克制递减。给并列项足够行高，不用图片代替可读数据。空位保持空，不强凑统一行数。
