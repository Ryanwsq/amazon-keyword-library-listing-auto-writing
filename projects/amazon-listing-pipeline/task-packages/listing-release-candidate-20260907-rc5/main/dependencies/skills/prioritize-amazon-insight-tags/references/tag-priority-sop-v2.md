# 场景 / 人群 / 用途 / 频率标签优先级决策 SOP

版本：V2.0  
固定输入：2 个 Excel  
固定输出：1 个 Excel，必须包含 5 个指定 Sheet

---

# 一、工作职责

本流程只负责完成以下工作：

1. 读取本品产品信息；
2. 读取竞品的人群、场景、用途、特点与痛点信息；
3. 将竞品原始表达归一化为统一语义标签；
4. 统计每个标签的竞品覆盖率；
5. 根据竞品 Amazon Listing 资源位，计算每个标签的介绍程度；
6. 使用“覆盖率 + 介绍程度”对标签进行市场分类；
7. 将标签与本品参数、结构和卖点进行对比；
8. 最终产出本品应使用的人群、场景、用途、频率标签及其内容优先级。

本流程不再重复验证消费者需求是否真实存在。竞品人群、场景、用途数据视为已经由 Alexa / 评论等上游流程抓取完成。

# 三、有效竞品判定

竞品必须以 ASIN 为唯一统计单位。

一个 ASIN 同时满足以下条件，才属于有效竞品：

1. ASIN 格式有效且身份没有错配；
2. 人群、场景、用途三个字段均已执行；
3. 三个字段不属于“身份异常 / 未执行 / 技术停止”；
4. 至少能提取一个有效的人群、场景或用途语义标签；
5. 同一父体的重复子体如果内容基本一致，只保留一个代表 ASIN，避免重复放大覆盖率。

有效竞品总数不得少于 10 个。

少于 10 个时：

> 可以生成 5 个输出 Sheet 和试算结果，但所有最终优先级必须标记“样本不足，不得作为正式结论”。

# 四、固定标签类型

最终只使用以下 4 类标签：

| 标签类型 | 回答的问题 | 示例 |
|---|---|---|
| 人群 | 谁在使用 | Players / Students / Big & Tall Users |
| 场景 | 在哪里或什么情境下使用 | Home Office / Gaming Room / Bedroom |
| 用途 | 想完成什么 | Work / Gaming / Relax / Reading |
| 频率 | 使用多久、使用多频繁或强度多高 | Daily Use / Long Hours / Occasional Use |

原流程中的“使用方式”不再作为独立固定输出类型。确有价值的使用方式，应根据语义归入“用途”或“频率”。

## 频率标签的硬规则

频率只能从明确表达中提取，例如：

- daily / every day → Daily Use；
- all day /全天 → All-Day Use；
- long hours /长时间 → Long Hours；
- gaming marathon / prolonged sessions → Extended Sessions；
- occasional /偶尔 → Occasional Use。

禁止因为“办公、游戏、学习”等用途通常持续较久，就自行推断 Long Hours。

原始数据没有明确频率表达时，频率标签必须留空，不得补写。

# 五、标签归一化

## 5.1 统计词意，不统计具体词

语义相同的表达必须合并。例如：

| 原始表达 | 统一标签 |
|---|---|
| work from home / WFH / remote work | Home Office |
| gaming / video gaming / esports | Gaming |
| content creator / streamer / live streamer | Content Creators / Streamers |
| long work sessions / prolonged sitting / long hours | Long Hours |
| reading and relaxing / reading & leisure | Reading / Relaxing |

## 5.2 一个 ASIN 对同一标签最多贡献一次覆盖

同一 ASIN 中同义标签重复出现时：

- 必须保留原始表达；
- 必须合并为一个统一标签；
- Coverage 只能计 1 次；
- Listing 同一资源位内也只能计 1 次 Expression。

## 5.3 来源标记处理

`〔A〕`、`〔B〕`等抓取轮次标记只用于追溯来源，不属于标签内容。

归一化时必须删除来源标记，但在“原始表达”字段中保留完整原文。

## 5.4 禁止跨类型重复计数

同一语义只能进入最匹配的标签类型。

例如：

- “长时间办公”拆分为用途 `Work` + 频率 `Long Hours`；
- “家庭办公室”归入场景 `Home Office`；
- “远程办公人员”归入人群 `Remote Workers`。

# 六、竞品覆盖率 Coverage

Coverage 回答：

> 这个人群、场景、用途或频率标签在竞品中有多普遍？

公式：

**Coverage = 覆盖该统一标签的有效竞品数 ÷ 有效竞品总数**

固定分级：

| Coverage | Coverage 等级 |
|---:|---|
| 100% | Absolute Consensus / 全竞品共识 |
| 80%–99.99% | 高覆盖 |
| 50%–79.99% | 中覆盖 |
| 20%–49.99% | 低覆盖 |
| ＜20% | 极低覆盖 |

Coverage 只能说明市场共识，不能单独决定最终优先级。

---

# 七、标签介绍程度 Expression

标签介绍程度回答：

> 覆盖这个标签的竞品，愿意使用多少重要 Listing 资源来介绍它？

## 7.1 自动抓取动作

对输入 2 中的每个有效竞品 ASIN，必须直接核验Run锁定站点的Amazon Listing（US=`amazon.com/10001`；DE=`amazon.de/80539`），并抓取以下区域。进入非锁定站点时停止受影响行并通知用户介入：

### 核心资源位

| Listing 区域 | 权重 |
|---|---:|
| Title | 2 |
| 前部核心副图，默认 Image 2–4 | 2 |
| Bullet 1–2 | 2 |
| A+ 首屏 / 核心模块 | 2 |

### 次级资源位

| Listing 区域 | 权重 |
|---|---:|
| 后部副图 | 1 |
| Bullet 3–5 | 1 |
| A+ 其他模块 | 1 |

Amazon 主图默认不参与人群、场景、用途、频率标签的 Expression 计算。

## 7.2 单 ASIN × 标签介绍度

同一标签在同一资源位重复出现，只计 1 次。

公式：

**Expression Score = Title×2 + Image 2–4×2 + Bullet 1–2×2 + A+核心×2 + 后部副图×1 + Bullet 3–5×1 + A+其他×1**

理论最高分为 11。

固定分级：

| 单竞品 Expression | 介绍等级 |
|---:|---|
| 6–11 | 高介绍 |
| 3–5 | 中介绍 |
| 1–2 | 低介绍 |
| 0 | 未介绍 |

## 7.3 标签市场平均介绍度

只统计已经覆盖该标签、且 Amazon Listing 已成功核验的竞品。

公式：

**Market Expression = 覆盖标签且 Listing 已核验的竞品 Expression Score 总和 ÷ 对应竞品数**

固定分级：

| Market Expression | 市场介绍等级 |
|---:|---|
| ≥6 | 高介绍 |
| 3–5.99 | 中介绍 |
| ＜3 | 低介绍 |

如果 Listing 无法访问：

- 抓取状态标记“未验证”；
- 不进入 Market Expression 分母；
- 不得按 Expression = 0 处理；
- 必须在输出中显示介绍度有效样本数。

# 八、标签市场分类

标签市场分类只使用 Coverage 和 Market Expression，不在这一步加入本品参数。

| 市场分类 | 固定条件 | 含义 |
|---|---|---|
| A｜必要表达候选 | Coverage ≥80% 且 Market Expression ≥6 | 市场高覆盖、高介绍，属于强类目共识 |
| B1｜普及但弱介绍 | Coverage ≥50% 且 Market Expression ＜6 | 市场普遍出现，但竞品没有投入足够核心资源 |
| B2｜细分强介绍 | Coverage 20%–79.99% 且 Market Expression ≥6 | 覆盖并非最高，但覆盖者高度重视 |
| C｜次级 / 观察 | 其他全部情况 | 市场信号较弱或尚未形成稳定共识 |

该规则已经覆盖 `Coverage 50%–79% + Expression≥6` 的情况，固定归入 B2，不得再标记为规则空白。

Coverage ＜20% 时，无论 Expression 多高，市场分类固定进入 C / 观察，不占核心资源。

# 九、标签与本品参数对比

标签完成市场分类后，必须与输入 1 的本品参数进行对比。

只允许使用以下证据：

- 本品尺寸参数；
- 本品结构；
- 本品材料；
- 本品功能；
- 本品配件；
- 本品明确卖点；
- 输入 2 中竞品特点与痛点；
- 可复核的竞品 Listing 事实。

不得自行补充产品没有提供的属性。

## 9.1 Direct Fit｜直接适配性

| 分数 | 固定判断 |
|---:|---|
| 2 | 本品属性直接帮助完成该人群、场景、用途或频率需求 |
| 1 | 存在间接关系 |
| 0 | 没有明确关系 |

## 9.2 Differentiation｜产品优势性

| 分数 | 固定判断 |
|---:|---|
| 2 | 参数明显领先、存在竞品普遍没有的结构，或多个属性形成明显解决方案 |
| 1 | 本品能够满足，但主要竞品普遍也具备 |
| 0 | 无优势、证据不足或无法确认 |

无法确认时固定记 0，禁止猜测。

## 9.3 Proofability｜可证明性

| 分数 | 固定判断 |
|---:|---|
| 2 | 可以通过参数、结构图、尺寸图或明确事实直接证明 |
| 1 | 可以合理说明，但证据一般 |
| 0 | 无法可靠证明 |

## 9.4 Product Advantage

公式：

**Product Advantage = Direct Fit + Differentiation + Proofability**

| 分数 | 产品关系 |
|---:|---|
| 5–6 | 强 |
| 3–4 | 中 |
| 0–2 | 弱 |

# 十、最终内容优先级

最终优先级必须在“标签市场分类”完成后，再经过本品参数闸门。

| 内容优先级 | 固定条件 | 输出动作 |
|---|---|---|
| 优先级 1｜必须表达 | 市场分类 A，且 Direct Fit ≥1、Proofability ≥1 | 进入本品最终核心标签；必须在 Listing 中出现 |
| 优先级 2｜重点宣传 | 市场分类 B1 或 B2，且 Product Advantage ≥5、Direct Fit ＞0 | 进入核心图片、Bullet 前部或 A+ 核心模块 |
| 优先级 3｜补充表达 | 不满足优先级 1/2，但 Direct Fit ≥1、Proofability ≥1 | 可用于后部图片、Bullet 后部、A+ 补充模块 |
| 不采用 / 观察 | Direct Fit =0，或 Proofability =0，或产品事实不足 | 不进入正式 Listing 标签；保留观察原因 |

注意：

- A 类代表市场必要信息，但本品不具备或无法证明时不得虚假宣称；
- B1 只有在本品存在强优势时，才能转化为重点宣传机会；
- B2 代表细分强信号，同样必须通过 Product Advantage ≥5 的闸门；
- 市场没有表达，不等于本品必须表达；
- 产品有功能，也不等于该标签值得占用核心资源。

# 十三、禁止事项

执行时禁止：

1. 把同义词当成不同需求重复统计；
2. 把一个 ASIN 的同一标签重复计算多次 Coverage；
3. 根据常识推断用户频率；
4. 把“未抓取到 / 未执行 / 页面无法访问”当作 0；
5. 因为竞品没有讲，就直接判断本品应该重点讲；
6. 因为竞品都讲，就直接判断本品应该放最大视觉资源；
7. 使用未提供的本品参数证明标签；
8. 使用营销语言代替产品结构或参数证据；
9. 在 Coverage、Expression 和 Product Advantage 之外增加主观优先级；
10. 输出不包含固定 5 个 Sheet 的结果文件。

# 十四、最终决策链

每个进入优先级 1 或优先级 2 的标签，都必须形成完整链条：

**谁（人群）**

↓

**在什么情况下（场景）**

↓

**想完成什么（用途）**

↓

**使用多久或多频繁（频率；没有明确证据时允许为空）**

↓

**本品哪个参数、结构或功能能够支持**

↓

**为什么比主要竞品更适合，或为什么必须表达**

如果最后两步无法用产品事实完成，该标签不得进入优先级 1 或优先级 2。

---

# 十五、固定原则

整个模型只使用以下三组核心判断：

## Coverage

回答：市场是否普遍存在这个标签？

## Market Expression

回答：竞品愿意使用多少 Listing 资源介绍这个标签？

## Product Advantage

回答：为什么这个标签适合由本品表达？

固定逻辑：

> 高覆盖 + 高介绍 → 必要表达候选

> 中高覆盖 + 低介绍 + 本品强优势 → 重点宣传

> 低中覆盖 + 高介绍 + 本品强优势 → 细分重点

> 只有市场信号、没有本品事实支持 → 不占核心资源

> 没有明确频率原文 → 不输出频率标签
