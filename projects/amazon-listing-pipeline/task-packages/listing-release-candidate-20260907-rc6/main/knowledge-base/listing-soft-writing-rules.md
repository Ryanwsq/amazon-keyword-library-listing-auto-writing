## 1. 执行顺序与字段分工

锁定当前Run、事实、06、已确认07 → 内容规划 → 草案与自检 → 主线程与用户确认全部实际文字 → 最终ST/09实际覆盖/10装配。规则生效不代表文案已确认。

Title先排库内候选搜索量，再对照卖点选词；IH先排除Title已表达卖点（含T0），再按剩余卖点优先级补充。两者尽量用足75/125字符、均无颜色、不要求自然句。**Bullet仍须自然连贯、让买家想象实际使用**，不是把Title/IH罗列方式拉长。

T0/T1/T2沿用确认顺序及原P0身份映射，不把展示序号当新权重，不重排07。

### 前台文案先排除已确认劣势（FRONT-COPY-DISADVANTAGE-EXCLUDE-01）

- 卖点选择保留用户确认的最强T0；其余通用卖点沿用已确认的重要程度顺序，逐项核对本品优劣势，遇到已确认劣势就跳过，后面的合格卖点依原相对顺序补位。Title、Item Highlight及全部Bullet不写入被排除的劣势卖点/参数；不因排名高而保留劣势，也不为补位重新发明排序。
- 此为卖点内容顺序，不改变Title关键词“先按原搜索量排序，再与确认卖点对照”的流程，也不恢复Title与IH重复T0。若T0本身与最新劣势结论冲突，回主线程确认；不能把某项劣势参数包在T0下面绕过排除。
- “事实是真的”“关键词有搜索量”“需要配置参数背书”“要填满字符/条数”都不能使已确认劣势重新进入这三个字段；不通过换单位、同义改写或包装成积极收益绕过排除。
- 劣势判断须有当前Run对比结论或用户明确确认；低优先级、普通通用配置、未知或样本不足不自动等于劣势。未确认优势也不能擅自写成领先优势。
- 保留源卖点/事实ID、劣势判定依据、被排除的字段及替代信息任务。此处改变前台内容选择，不篡改事实卡、原始对比、06词库、已封存07或历史交付；当前用户新增选择另存证据，供后续修订使用。
- 本轮Gaming Chair用户明确把300 lb承重指定为劣势：Title/IH/Bullet均排除，不再用它为Big & Tall定位背书。真实最大承重仍为300 lb，不能据此暗示更高承重、适合所有体型或删除商品属性、说明书等应保留的限制。
- 本规则不是隐瞒必要安全/适配条件的授权。若某主张只有同时披露该限制才不误导，或已知后台强制要求该字段披露，标出冲突并改写/放弃该主张或交用户确认，不用营销排除规则覆盖必要披露。主图/A+、Q&A及内部参数展示不因本次三字段限制自动重排。

## 2. 条数、长度与动态内容框架

沿用“五点描述”称呼，用户最新要求**至少5条，通常5–6条，按完整覆盖和自然可读性确定，不默认凑六条**。先将共同服务同一用途的卖点自然组合，再核对必要信息是否全部覆盖：五条已讲完整就停在五条；确有独立理由或较多配件需要展开时才用第六条。下面是五类内容块，不是机械的一块一条：

| 顺序 | 内容块 | 填充逻辑 |
|---|---|---|
| 1 | T0卖点 | 最强T0一般第一，按内部确认顺序展开；可有1–2个或更多，独立核心理由可分别占条，后续顺延 |
| 2 | T1关联组合 | T1主卖点结合共同服务同一用途的其他卖点，自然融入匹配的高优先标签 |
| 3 | T2关联组合 | 同上，不为塞配置而加入无关用途 |
| 4 | 配置证据或真实配件价值 | 按CATEGORY-CONTENT-ROLE-01分流：本体配置用于证明相关卖点，可融入对应条；只有真实随附配件具有成套价值时才集中交代配件。不把整椅部件罗列成配件清单，不把劣势当背书 |
| 5 | 售后服务 | 只写确认的保修期限/范围、客服时段/回复时效，无政策不虚构 |

两个T0时可形成：T0-1 → T0-2 → T1组合 → T2组合 → 配置背书 → 售后的六条结构，但不因有两个T0就机械要求六条。不得为凑第六条拆开本应合讲的配置、重复场景/收益或虚构内容；也不得为压到五条漏掉重要信息或把无关主题硬塞在同一条。售后未知就暴露缺口或讨论其他真实独立主题，不虚构承诺补足最低五条。

本次桨板卖点和配件较多，现有六条保留；电竞椅若五条自然覆盖完整就用五条，不强补第六条，也不允许少于五条。这是本次内容判断示例，不是“桨板固定六条、电竞椅固定五条”的类目模板。

写前记录“必要信息/卖点 → 对应Bullet → 合讲理由”及已确认劣势排除清单，写后确认剩余合格T0、重要通用卖点、必要配置/配件、适配信息及已确认售后无遗漏，条间无凑数复述；覆盖完整不等于把劣势补回文案。五或六条均随实际正文一并交互确认，不另设“五条例外审批”。若确需超过六条，先确认目标环境可用条数和用户安排，再锁定依据；不得由六条实测推断任意条数可上传。

不设项目字符最低值、目标区间或上限，不按旧255/500截短、不设长度例外。参考用户长版样稿的信息密度，不将其字符数变成新门槛。每条报告真实计数；六条长版可上传是用户当前环境实测，不泛化为所有站点类目。

### 本体卖点、配置证据与随附配件分流（CATEGORY-CONTENT-ROLE-01）

- 写前根据当前SKU的实际销售构成，标记每项内容是本体功能卖点、支撑卖点的配置参数，还是具有独立随附价值的配件。上游字段写着“组件/Included Components”或某部件可拆装，都不等于适合写成配件卖点。
- 本轮电竞椅的靠背、弹簧海绵坐垫、头枕、扶手垫、按摩腰枕、脚托属于整椅功能或配置。按重要性放入对应购买理由，讲部件怎样服务坐用体验；不能最后再列一遍“包含头枕、腰枕、脚托”等，冒充完整配件包或凑第五条。
- 桨板实际随附的桨、泵、背包、收纳袋等，具有出行整备、划行、收纳或携带价值，可以安排真实配件条。若保冷包、充气座椅等本身是高优先级卖点，仍在前面的对应用途条充分展开；配件条只承担配置核对/整备任务，不把每个卖点重讲一次。桨板尺寸、板体材质等仍是本体卖点，不因同属桨板就归为配件。
- “配置背书”是一种证据表达方式，不是所有类目都必须独立占一条；“配件清单”也不是固定的第五条或末条。末条依尚未覆盖的合格购买理由或已确认售后安排，不机械跨类目复制桨板模板。
- 电竞椅等本体主导产品可以把相关功能合讲，但必须有一个清楚的使用目的和新增信息。仅把多个部件名称串联，末尾再加“带来支撑/舒适”等空泛总结，仍然是罗列配置，不算用途组合。
- 不以新增条目、重复既有卖点、罗列整椅尺寸或虚构售后满足至少五条。若排除劣势、合并重复后缺少足够的独立主题，列明需要补充的产品价值/事实供讨论；不得私自降低五条要求，也不得用部件清单填补缺口。

## 3. 每条：从“有什么”到“怎样用”

写前确定：主购买理由｜卖点等级/源ID｜内容角色（本体卖点/配置证据/随附配件）｜关联配置/参数｜适合的标签及顺序｜动作/情境｜使用变化｜事实依据｜补充关键词｜条间分工。

1. 先按卖点优先级定主题，再按用途关联组合配置，最后在**匹配本条的标签**中依优先级选人群、场景。不得强塞不相关高频标签或要求每条写全部维度。
2. 一条一个主要购买理由，不是一条只能讲一个配置。讲“买家想做什么—哪些部件怎样配合—用起来有什么变化”，不止“包括X、提供Y”。
3. 自然而不简单化。用动作、物件、时刻、具体参数形成画面，可先说体验再说明结构；避免所有条都套相同模板或只写舒适/方便。
4. 按FRONT-COPY-DIMENSION-EXPRESSION-01先写买家能感知的空间/使用价值，参数只在帮助理解、比较或判断适配时作背书。不是核对尺寸清单，也不要求每条必须写数字；承重不能直接推成人数、安全保证或水域性能。
5. 同一配件可服务多个用途，再次出现须增加新用途、机制或选购信息，不只换场景重复收益、挤掉其他重要卖点。
6. 按CATEGORY-CONTENT-ROLE-01决定是否需要独立配置证据或配件条；本体部件应服务相关卖点，不因“允许配件清单”就罗列整机功能。真实随附配件可集中交代，但不自动夸成无需其他装备。
7. 每个分句新增事实、机制、动作、收益或必要边界；删空泛自夸、复述和无依据的全天不累/永不塌陷/保冷时长/安全保证。取消限制不等于必须写长。
8. 简短描述性标题头加冒号；允许多句自然展开，内部句号/分号按语义用，末尾仍不加结束标点。不按旧“只能片段/只能分号”割碎叙述。

### 五点中的尺寸与使用画面

完整尺寸准入见[标题与亮点知识库](listing-title-highlight-writing-rules.md)的FRONT-COPY-DIMENSION-EXPRESSION-01。写Bullet时进一步检查：

- 先让买家知道空间能让自己怎样坐、移动或放置装备，再用必要数字证明；“坐垫宽X、靠背宽Y”本身不是独立购买理由，也不因后面加“舒适”就获得画面感。
- 本轮电竞椅的宽大定位用已确认的extra wide seat及坐下、调整位置、靠回椅背等相关动作表达，不机械重复21.3 in坐垫/靠背宽度。标题/IH没有写数字，不构成Bullet必须补齐这些数字的理由。
- 本轮桨板尺寸本身有用户确认的选购意义，可以把12 ft × 36 in与站立、移动或装备空间合讲；不是禁止数字，也不能超出已确认事实宣称市场最大或容量保证。
- 有实际适配意义的尺寸及必要限制仍应准确交代，保留原单位和来源；后仰90–135度帮助理解坐直到休息的功能范围，可以与动作合讲。用定性词隐藏必要限制或包装已确认劣势仍不允许。
- IH可省去与袋装弹簧同属坐垫支撑理由的次要海绵短语；Bullet若解释两种已确认结构怎样配合，则不因IH省略而自动删除。是否保留取决于新增信息和事实，不能回到无目的的配置堆叠。

## 4. 附加埋词与重复

先有内容，再补词；执行细则见总控keyword-allocation.md。

- 只取当前06；先剔除Title、IH已埋关键词的主动候选，再参考余词原月搜索量与本条主题匹配度自然写入。
- 不因流量重排卖点、造场景或牺牲可读性。语法变化须追溯原词与实际片段，不虚报完整短语命中。
- Title/IH已有卖点仍可深入说明，必要品类词/事实用语可重复，不等于再分配相同主动埋词目标。
- 去重粒度须登记。本轮尚未确认词组还是词根算法；计划可提出按源关键词/完整词组去除、共有词根允许自然复用的建议，正文讨论时确认，不能默认禁止所有共有词根。与ST去重口径分别记录。
- 图组标签复现规则不硬套Bullet；未采用、观察、未知标签不转为正式承诺。

## 5. 售后与直接竞品

保修期限、范围、在线时段、回复时效分别使用品牌/SKU已确认政策。24/7支持不等于24小时内回复，不互换；无政策不自动填2年、3年或24/7。符合已知后台边界的真实保修/支持可以表达；不写退款、满意度、无条件、无风险保证，不加站外联系方式或引导联系卖家。

事实优先于感染力。用户明确标为本品的参考稿可登记为该SKU人工补充来源；冲突或身份不明参数仍待确认，不变成跨SKU通用知识。Alexa未识别不是产品没有，样本未提及不是独有证明。

可参考直接竞品的收益入口、信息展开、动作及节奏，登记来源/ASIN（已知时）、日期及新旧标题。只借组织，不照抄原句、不继承数字、配置、品牌、保障、效果或库外词源。不改变Alexa-only上游，不宣称某写法必然提升转化。

## 6. 质量检查与交互

硬性违规、事实待确认和软性质量（通过/可优化/质量缺口）分别报告：

1. 是否保留已确认T0；其余通用卖点按重要性顺序检查并跳过劣势，合格项依原顺序补位，未被流量倒置？
2. 是否每条一个独立购买理由；部件怎样作用、买家怎样用是否讲充分？本体部件是否误写成随附配件，是否把桨板配件条机械复制到电竞椅？
3. 标签是否匹配自然，非强行加入或反复换词？
4. Title/IH/Bullet是否均未写入已确认劣势；参数背书是否从剩余合格内容中选择，清单是否准确，售后是否有政策？必要披露冲突是否已解决，而非省略限制制造误导？
5. 关键词来自06且排除已分配Title/IH的主动目标，英文仍自然？
6. 再次出现的配置是否有新作用；没有只有抽象舒适/方便或堆参数？
7. 至少五条；五条完整就不补第六条，第六条确有新增必要信息？覆盖清单无遗漏、无强行拆分或过度合并，实际计数可见；超过六条有环境/条数确认依据，没有恢复字符门槛？
8. 竞品只借写法，事实未转移？
9. Title、IH、全部Bullet及未决取舍已展示确认；文字和来源哈希一致？
10. 尺寸是否转化为买家可理解的空间/动作；出现的数字是否确有比较、功能或适配任务？定性“加宽”等是否有当前事实/确认支持，必要限制是否仍保留？

局部改稿另存供确认，不把“写一版”当批准正文；未确认不重算最终ST、不装配10、不改历史状态。规则/脚本检查通过不等于用户认可文案或Amazon审核通过。
