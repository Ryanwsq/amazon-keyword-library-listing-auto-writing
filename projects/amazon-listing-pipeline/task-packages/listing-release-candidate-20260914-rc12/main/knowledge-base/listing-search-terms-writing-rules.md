# Search Terms 选词与写法

版本：`ST-WRITING-20260911-01`。适用：Amazon-US / Amazon-DE 新锁定规则版本的 Listing 写作与装配；不追溯切换正在运行或封存的 Run。

本文件区分官方指导、项目执行规范和卖家经验。平台限制见[ST硬性规则](listing-hard-rules/亚马逊ST硬性规则.md)。仅补齐 ST，不改变关键词采集优先级、06 准入、Title/IH/Bullet 写法、两道人机确认或工作簿表头。

## 1. 定位与输入

ST 是后台 `generic_keywords` 的补充搜索词，不是广告搜索词报告，也不是前台文案、关键词垃圾桶或合规规避区。官方仍建议使用后台词补充前台未自然覆盖的同义称呼、缩写及其他相关词；不能承诺收录、排名、转化率或 Rufus 会引用。[官方 SEO 指南，第 5 节](https://sell.amazon.com/blog/amazon-seo)

只消费当前已验收 `06_SKU可用关键词库.xlsx` 的 `SKU可用关键词库` Sheet、锁定事实、07 的 ST 去重范围和已确认的实际 Title/IH/全部 Bullet。保留 Keyword_ID、源行、原词与原指标。其他广告报告、文章、工具推荐、翻译或模型联想仅能提出下一次词库更新需求，不能直接绕过 06 写入最终 ST。主任务只编排和验收，不代写。

07 阶段提出并锁定“Title + IH + 全部 Bullet + ST 内部，逐词去重”的执行口径；它是本项目写法，不是将平台的冗余建议改写为所有字段的绝对禁词。不得省略原有确认门或静默扩大已确认范围。最终 ST 必须在第二道正文确认后生成；前台有修订则重算去重结果和受影响的确认/装配证据，不沿用旧 ST。

2026-09-14用户补充：后续新写作按上述完整前台范围登记07，不再退回“只排除Title”或漏掉Item Highlights；历史已确认范围不静默改写。执行的是ST候选逐词排除，不禁止正文各字段为清晰表达自然复用必要品类词，也不禁止真正提供新检索表达的有源同义词。

## 2. 选什么、不选什么

- 优先选择 06 中与本品真实匹配、前台没有覆盖的补充称呼、同义词、常用缩写、合法拼写变体及具体用途/场景/人群长尾。ST 可以承接前台不适合自然展开的词，但不为了 ST 故意撤掉前台必要产品身份或卖点。
- **同义词不等于重复词。** 不因 `tv` 与 `television` 意义近似就全部删除；是否采用仍看本品、06 来源和前台实际覆盖。官方明确鼓励同义词和替代称呼。[Amazon 官方公告](https://sellercentral.amazon.com/seller-forums/discussions/t/62e0e515a6e991d171d3ccee7be36304)
- 合法地域拼写与错拼分开：可考虑已在 06 的合格拼写变体；不主动制造错别字或故意错拼品牌。常见错拼通常由系统纠正，不以“低竞争”绕过上游文本质量门。[Amazon 官方提示](https://sellercentral.amazon.com/seller-forums/discussions/t/923d53dc-a182-4475-a164-6b2500dbaf2d)
- 单复数若只是同一词的相同意图，通常保留一种；由写作角色核对，不机械删尾部 `s`，不把所有共享词根的词视为同义。`glass`、`glasses` 等须结合产品和真实意图判断；不得改写 06 原词。
- 普通冠词、连接词、介词在 ST 中通常无须保留，但先检查删除会否破坏含义。否定、限制或固定表达不能盲删；尤其不能把“不含某配件”删成“含某配件”的搜索承诺。无法保持准确含义时放弃该候选，不把危险残片塞入 ST。
- 自有品牌、竞品品牌、ASIN、内部 SKU/识别码、促销和主观夸大等仍按硬规则排除。`compatible with` 等前缀不使 ST 中的品牌合法；前台兼容性表达是另一字段规则，不能挪用。
- 医疗、认证、适配、材质、随附配件等必须有当前事实和合规依据。节日词不是自动准入：真实主题/用途且已通过 06 才能评估；不得因临近节日直接添加 `christmas gift` 或借节日写限时促销。不能把 `gift`、人群或大流量泛词设成必填。

## 3. 逐词去重，不伪造完整短语覆盖

执行顺序：已确认前台 → 候选规范化 → 删除已覆盖词 → ST 内部去重 → 剩余片段语义复核 → 预算取舍。

1. 为比较建立 Unicode NFC + 小写副本；原始 06 词和确认正文不变。标点作为边界，不能直接删标点粘成新词。德语正常保留 `ä/ö/ü/ß`，不机械转写或拆复合词。
2. 精确词边界比较，不用子串：`seat` 不等于 `seating`，`arm` 不等于 `armrest`。单复数/词形等语义合并另记理由，不让正则替代判断。
3. 删除已在人工锁定前台范围出现的词；余词可以来自多个合格源词，但逐词保留来源映射。内部只出现一次，不因另一长尾又含 `chair` 而反复加入。
4. 区分“所有词元已经出现”和“完整词组在同一字段连续出现”。例如前台 `gaming, chair support` 含两个词元，但不能记为连续短语 `gaming chair` 命中；不同 Bullet 或前台/ST 拼接也不算完整短语覆盖。
5. 不把拆出的词元或合成 ST 串继承为一个有原搜索量的新关键词。搜索量只附原始源词；缺值不填 0，不求和制造新组合流量。
6. 记录剔除原因：前台已有、ST 已有、事实/合规不符、无来源、含义风险或预算不足。ST 不采用不改变 06 的“保留”结论。

本项目图片/A+当前只做标签位置预览，不把图片上的字或未生成的 Alt Text 当成已完成前台埋词来删 ST；确有额外正文/属性字段需要去重时在 07 显式锁定，不能猜测内容已被平台索引。

## 4. 排序与字节预算

这是项目的可解释取舍，不是 Amazon 权重公式：先保证合规、真实性、06 来源和未覆盖条件；优先保留明确匹配产品的补充称呼及具体高意图长尾，再补其他合格场景/人群/用途词。不是将“核心词”重复塞回已写标题的字段，也不是无条件“场景词排最后”。

同样匹配、同样有新增覆盖价值的候选，可按 06 原搜索量及当前已确认重要性取舍；若没有可信转化证据，不称“高转化词”。没有新增打分、搜索量阈值或流量加权算法。顺序用于稳定交付和预算裁剪，不宣称前置有索引加权。

- 最终只输出一行小写词，单个普通空格分隔；不是完整营销句，不用引号包词组，不加 `Search Terms:` 标签或标点。
- 按最终原样文本计算 UTF-8 字节，含空格；这是项目保守验算方式，不声称所有后台历史计数器都完全同口径。ASCII 大小写都为 1 byte，小写是格式规范，不是节省字节的原理。
- US 延续 `<250 bytes`，即最多 249；更严格的当前后台限制优先。DE 仍须锁定本次站点/类目证据，未核验不默套 US；中文/德语字符不能按英文字符数估算。
- 不必填满，不新增 230–245 的强制目标/最低值。超预算优先整体放弃低优先级的候选新增片段并记录原因；不得切断 UTF-8 字节、单词或产生误导残片。补入其他短词也须同样准入，不能为填空造词。
- 多个界面输入框不代表每框独立拥有同一预算；本项目交付一个已校验 ST 总串，按适用属性/模板总限制处理，不靠拆框绕过上限。

## 5. 写法示例（合成说明，不是当前 SKU 事实或可直接使用的词库）

假设当前 06 已验收四个相关候选：`gaming chair footrest`、`gaming chair lumbar support`、`computer gaming chair`、`gaming seat`；确认前台已出现 `gaming chair`、`footrest`、`lumbar support`，但没出现 `computer`、`seat`。

| 原候选 | 处理 | 新增 ST 词 |
|---|---|---|
| gaming chair footrest | 三个词均已在前台，不重复 | 空 |
| gaming chair lumbar support | 四个词均已覆盖，不重复 | 空 |
| computer gaming chair | 去掉已有 gaming/chair，保留有源新增称呼 | computer |
| gaming seat | 去掉 gaming，保留有源词 seat | seat |

最终示例：`computer seat`，UTF-8 为 **13 bytes**。短不等于不合格；不为满 249 bytes 增加未验收词。这是来自两条源词的补充词串，不能称为原词库存在 `computer seat` 或给它赋搜索量。

反例：`Gaming Chair, gaming chairs BEST BrandExample B000000000 free shipping`。问题分别是格式、重复及可疑复数冗余、主观词、品牌/识别码、促销；不能仅转成小写就通过。

德语编码示例：`bürostuhl` 是 9 个字符、**10 bytes**；这是计数示例，不证明某把椅子可用该词。保留真实德语拼写，不因超字节就随意去变音符；当地常见另一写法必须有 06 来源及语义依据。

## 6. 输出、自检与后续复盘

继续使用现有 09 的关键词分配、字段预算、排除词与原因，以及 10 的 ST/规则校验位置，不新增 Sheet 或改变表头。关联证据应可复核：当前 Run/marketplace、06 和正文快照哈希、07 去重范围、原 Keyword_ID/词/指标、新增词元和排除原因、最终 ST、UTF-8 字节/上限及来源、事实与禁词检查、词元覆盖与完整短语覆盖的区别。

写作角色在现有装配内自检一次，主任务接收证据；不新增独立质量任务。可用[机械检查脚本](../dependencies/skills/apply-amazon-listing-hard-rules/scripts/check_search_terms.py)辅助字节、格式、精确重复词检查。脚本不判商品相关性、词形、品牌完整清单、06 身份、人工门或 Amazon 索引，不把机械通过称成业务/P1通过。

复盘是可选的后续运营任务，不在本轮交付后自动安排每季度任务、不改后台、不建广告。只有用户另行授权后，才结合真实广告搜索词报告/搜索表现、库存、季节和前后台版本做对照；广告表现不能直接归因为 ST，自然搜索无曝光也不等于某词失效。更新词源仍回到独立关键词流程和 06 准入。保存旧版、变更原因和观察窗口，不能用刷单/排名操纵验证权重。ASIN+词搜索、后台保存成功或 Rufus 单次回答均不是完整索引/排名证明。
